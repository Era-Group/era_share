🔌

Claude with no API billing

Routes chat through the locally-authenticated claude CLI (the connected account). The first-party tool makes the call under its own auth — credentials are never read or replayed.

🧩

Every major provider

OpenAI, Google Gemini, Anthropic (native Messages API) and any OpenAI-compatible gateway (OpenRouter, Groq, Together, local) — connected by key.

👥

Shared & personal accounts

One account for everyone, or per-user accounts. An owner plus an allow-list and record rules decide exactly who can use each one.

🔄

Dynamic model catalog

Models are synced per account — version-proof aliases for the CLI, and a live /models pull for key accounts. No hard-coded model lists.

🔐

Encrypted & access-controlled

API secrets are Fernet-encrypted at rest and restricted to AI Account Managers. Shared users get a relation to the account, never the key.

🛡️

Cost & rate guards

Per-account concurrency cap and an instant kill switch keep subscription limits under control. Connections validate before use.

How it works

  1. Open AI ▸ AI Accounts and create an account — pick a provider and an auth mode (Local CLI proxy or API key).
  2. Click Validate connection, then Sync models.
  3. Set the scope (shared / personal), the owner and the allowed users.
  4. On any AI Agent, choose the AI Account and model — responses now run through it.

⚖️ Used responsibly

The CLI proxy invokes the sanctioned first-party tool; it never replays OAuth tokens to the raw API. Serving many users from one subscription draws on its rate limits — that's what the concurrency cap and kill switch are for.

ℹ️ Good to know (v1)

The CLI proxy is for chat / RAG agents; tool-driven "Ask AI" navigation needs an API-key account. Claude has no embeddings, so RAG keeps using the agent's standard embedding provider.
