ERA AI Client

عميل الذكاء الاصطناعي من ERA

Shared internal library that abstracts calling any configured AI provider — OpenAI, Anthropic, Gemini, Cloudflare, and more — from Python code in other ERA modules. One AIClient class, every provider, no duplicated HTTP logic.

مكتبة داخلية مشتركة تُجرّد استدعاء أي مزوّد ذكاء اصطناعي مُهيَّأ — OpenAI وAnthropic وGemini وCloudflare وغيرها — من كود Python في وحدات ERA الأخرى. فئة AIClient واحدة لجميع المزوّدين دون تكرار منطق HTTP.

🤖

Unified AIClient Interface

A single AIClient(env) class exposes three main methods: chat(messages) for conversational completions, complete(prompt) for single-turn text generation, and embed(text) for vector embeddings. Callers pass a list of message dicts in OpenAI format and receive a plain string or list of floats — they never need to know which provider is active or how its API differs.

واجهة AIClient الموحَّدة

فئة AIClient(env) واحدة توفّر chat للمحادثات، وcomplete للإتمام، وembed للتضمينات. يُمرِّر المستدعي قائمة رسائل بصيغة OpenAI ويحصل على نص أو قوائم أعداد عشرية — دون الحاجة لمعرفة المزوّد النشط أو خصائص واجهته البرمجية.

⚙️

Provider Abstraction Layer

Supports OpenAI chat completions, Anthropic Messages API (with system message handling), Google Gemini, Cloudflare Workers AI, and any OpenAI-compatible endpoint such as OpenRouter, Groq, or a local Ollama instance. Each provider is implemented as a thin adapter class. Adding a new provider means writing one new adapter — no changes are needed in any calling module.

طبقة تجريد المزوّدين

تدعم OpenAI وAnthropic Messages API وGoogle Gemini وCloudflare Workers AI وأي نقطة نهاية متوافقة مع OpenAI كـ OpenRouter وGroq وOllama. كل مزوّد فئة محوّل خفيفة — إضافة مزوّد جديد لا تتطلب تغييراً في الوحدات المستدعِية.

🔌

Agent & Tool-Call Support

Passes Odoo agent tool definitions (in JSON Schema format) to the model as part of the request and parses tool-call responses back into structured Python dicts. Any ERA module can implement agentic behaviour — iterative tool-use loops, database queries, record creation — with a few lines of Python. The client handles the multi-turn loop scaffolding automatically.

دعم الوكيل واستدعاء الأدوات

يُمرِّر تعريفات أدوات وكيل أودو (بصيغة JSON Schema) للنموذج ويُحلّل ردود استدعاء الأدوات إلى قواميس Python منظَّمة. أي وحدة ERA تستطيع تنفيذ سلوك وكيل — حلقات أدوات، استعلامات قاعدة بيانات، إنشاء سجلات — بأسطر قليلة من Python.

🔑

Secure Credential Resolution

API keys are resolved from ir.config_parameter at call time and never cached in process memory beyond the duration of the HTTP request. The client never logs keys, full prompt payloads, or model responses to Odoo server logs. Sensitive parameters are passed directly to the provider's HTTP layer without intermediate string formatting that could leak to stack traces.

استرجاع آمن لبيانات الاعتماد

تُسترجَع مفاتيح API من ir.config_parameter لحظة الاستدعاء ولا تُخزَّن في الذاكرة أبعد من مدة طلب HTTP. لا تُكتب المفاتيح ولا الموجّهات ولا الردود في سجلات أودو، مع تمرير المعاملات الحساسة مباشرة لطبقة HTTP.

📦

Consumed by All ERA AI Modules

era_seo_suite, era_recruitment_ext, era_crm_lead_spam_ai, and other ERA modules all import from era_ai_client.client import AIClient rather than implementing their own HTTP layer. This means provider upgrades, security patches, and new model support are delivered to every ERA AI feature through a single package update.

تستخدمه جميع وحدات ERA للذكاء الاصطناعي

era_seo_suite وera_recruitment_ext وera_crm_lead_spam_ai وغيرها تستورد AIClient بدلاً من بناء طبقة HTTP خاصة. ترقيات المزوّدين وتصحيحات الأمان ودعم النماذج الجديدة تصل لجميع ميزات ERA AI بتحديث حزمة واحدة.

🛡️

Error Normalisation

Provider-specific HTTP errors (OpenAI 429 rate-limit, Anthropic overload, Gemini quota exceeded), network timeouts, and malformed JSON responses are all caught and re-raised as AIClientError subclasses with a consistent message, provider, and status_code attribute. Calling modules handle one error type instead of maintaining provider-specific exception mappings.

توحيد الأخطاء

أخطاء HTTP الخاصة بكل مزوّد (حد معدل OpenAI، حمل Anthropic الزائد، حصة Gemini)، انتهاء المهلة، وردود JSON مشوَّهة — كلها تُحوَّل لاستثناءات AIClientError موحَّدة بسمات message وprovider وstatus_code. الوحدات المستدعِية تتعامل مع نوع خطأ واحد بدلاً من تعيينات متعددة.

How it works

  1. Another ERA module lists era_ai_client in its __manifest__.py depends list.
  2. In Python code it runs from era_ai_client.client import AIClient.
  3. It calls AIClient(self.env).chat(messages) — optionally passing tools, model, or temperature.
  4. The client resolves the active provider from Odoo settings, formats the request correctly for that provider's API, and returns a plain string response (or structured tool-call dict).

كيف يعمل

  1. تُدرج وحدة ERA أخرى era_ai_client في قائمة depends بملف __manifest__.py.
  2. في كود Python تُنفِّذ from era_ai_client.client import AIClient.
  3. تستدعي AIClient(self.env).chat(messages) مع تمرير tools أو model أو temperature اختيارياً.
  4. يحدّد العميل المزوّد النشط من إعدادات أودو، يُنسّق الطلب وفق واجهة ذلك المزوّد، ويُعيد نصاً أو قاموس استدعاء أداة.

ℹ️ Developer Library — No UI

This module ships no menus, views, or user-facing screens. It is installed automatically when any dependent ERA module is installed. At least one AI provider must be configured in Settings → AI before AIClient can make calls.

الوحدة بلا قوائم أو نماذج — تُثبَّت تلقائياً مع أي وحدة ERA معتمدة عليها. يجب تهيئة مزوّد ذكاء اصطناعي واحد على الأقل في الإعدادات ← الذكاء الاصطناعي قبل تشغيل AIClient.

⚡ Single upgrade path

Because all ERA AI modules share this client, updating era_ai_client once delivers new provider support, timeout improvements, or security patches to every ERA feature simultaneously — no module-by-module patching required.

لأن جميع وحدات ERA للذكاء الاصطناعي تشترك في هذا العميل، يكفي تحديث era_ai_client مرة واحدة لتوصيل دعم مزوّدين جدد وتحسينات وتصحيحات أمان لكل ميزة ERA دفعة واحدة.
