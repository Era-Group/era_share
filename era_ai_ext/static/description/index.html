ERA AI Extension

امتداد الذكاء الاصطناعي من ERA

Non-invasive override for Odoo 19's built-in AI provider layer that adds a configurable request timeout. Long AI operations — bulk SEO, blog generation, multi-step agent loops — no longer hit Odoo's hard 30-second wall and fail silently.

تعديل غير متطفّل على طبقة مزوّد AI المدمجة في أودو 19 يُضيف مهلة طلب قابلة للتهيئة. عمليات الذكاء الاصطناعي الطويلة — SEO بالجملة، توليد المدوّنات، حلقات الوكيل — لن تنتهي بصمت بعد الآن عند 30 ثانية.

⏱️

Configurable Request Timeout

Adds the system parameter era_ai.request_timeout (value in seconds) to Odoo's parameter store. Administrators set it once in Settings → Technical → System Parameters and the new value takes effect immediately for all subsequent Odoo AI provider calls — no server restart, no code deployment. The default is 120 seconds, doubling Odoo's built-in 30-second ceiling.

مهلة طلب قابلة للتهيئة

يُضيف معامل النظام era_ai.request_timeout (بالثواني) لمخزن معاملات أودو. يضبطه المسؤول من الإعدادات ← التقني ← معاملات النظام ويسري فوراً دون إعادة تشغيل. القيمة الافتراضية 120 ثانية — ضعف سقف أودو المدمج البالغ 30 ثانية.

🔧

Non-Invasive Monkey-Patch

The timeout override is applied using Python's standard monkey-patch approach at module load time — the session timeout attribute on Odoo's AI provider HTTP session is replaced with the configured value. Odoo's core AI files are never modified on disk. When a future Odoo upgrade ships a new version of the provider layer, it installs cleanly and the patch reapplies automatically on restart.

تعديل غير متطفّل

يُطبَّق التعديل عبر monkey-patch بأسلوب Python القياسي عند تحميل الوحدة — يُستبدل سمة مهلة جلسة HTTP في مزوّد AI بأودو بالقيمة المُهيَّأة. لا تعديل على ملفات أودو الأصلية. ترقيات أودو المستقبلية تُثبَّت بنظافة ويُعاد تطبيق التعديل تلقائياً.

⚡

Fixes Long-Running AI Operations

ERA modules that send large prompts — SEO bulk-fill across dozens of products, blog article generation, Monte Carlo AI suggestions, and Google Search Console analysis — all involve context windows that exceed what Odoo's default timeout can accommodate. Without this module those jobs terminate mid-stream, leaving partial records with empty fields and no error message visible to the user.

يُصلح عمليات AI الطويلة

وحدات ERA التي ترسل موجّهات ضخمة — ملء SEO لعشرات المنتجات، توليد مقالات المدوّنة، اقتراحات Monte Carlo، تحليل Google Search Console — تتجاوز جميعها ما يستوعبه الحد الافتراضي لأودو. بدون هذه الوحدة تنتهي هذه الوظائف في منتصف المعالجة وتترك سجلات منقوصة.

🛠️

Zero Configuration After Install

After installation the module creates era_ai.request_timeout with a sensible default (120 s) if it does not already exist. No menus, no views, no wizards to navigate. The single parameter is the only knob — administrators find it by searching "era_ai" in System Parameters. Deployments with unusually long prompts simply increase the value; no other code changes are needed.

إعداد صفري بعد التثبيت

عند التثبيت تُنشئ الوحدة era_ai.request_timeout بقيمة افتراضية منطقية (120 ث) إذا لم تكن موجودة. بلا قوائم أو نماذج أو معالجات. معامل واحد فقط — يجده المسؤول بالبحث عن "era_ai" في معاملات النظام. التوزيعات ذات الموجّهات الطويلة تزيد القيمة فقط دون أي تغييرات أخرى.

How it works

  1. Install ERA AI Extension — the module registers its post-load patch automatically.
  2. Go to Settings → Technical → System Parameters, search for era_ai.request_timeout.
  3. Set the desired value in seconds (default: 120). Save.
  4. All subsequent Odoo AI provider HTTP requests use the new timeout — no restart needed.

كيف يعمل

  1. ثبّت ERA AI Extension — تُسجّل الوحدة تعديلها تلقائياً بعد التحميل.
  2. اذهب إلى الإعدادات ← التقني ← معاملات النظام، ابحث عن era_ai.request_timeout.
  3. اضبط القيمة بالثواني (الافتراضية: 120). احفظ.
  4. جميع طلبات HTTP لمزوّد AI في أودو اللاحقة تستخدم المهلة الجديدة — بلا إعادة تشغيل.

⚠️ Provider timeout vs. Worker timeout

This module patches the timeout at the provider HTTP session level — it controls how long Odoo will wait for the AI provider's response. It does not bypass Odoo's worker process timeout (limit_time_real in the server config). For operations expected to exceed 300 seconds, also raise limit_time_real in your odoo.conf file.

يُعدِّل الوحدة مهلة جلسة HTTP للمزوّد — تحكم في كم تنتظر أودو ردّ مزوّد AI. لا تتجاوز مهلة معالج أودو (limit_time_real في إعدادات الخادم). للعمليات التي تتجاوز 300 ثانية، ارفع أيضاً limit_time_real في ملف odoo.conf.

💡 Upgrade-safe design

Because the patch is applied in Python at runtime — not by editing core files — future Odoo point releases install cleanly and the override reactivates on next startup. If Odoo ever ships a native configurable timeout, this module can be safely uninstalled with zero residual changes to core files.

لأن التعديل يُطبَّق في Python وقت التشغيل — لا بتحرير ملفات أصلية — إصدارات أودو المستقبلية تُثبَّت بنظافة وتعود التعديلات تلقائياً عند التشغيل التالي. إذا أضاف أودو يوماً مهلة قابلة للتهيئة أصلاً، يمكن إلغاء تثبيت هذه الوحدة بأمان.
