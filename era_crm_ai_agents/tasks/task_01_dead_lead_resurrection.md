# Task 01 — Dead-Lead Resurrection Agent (وكيل إحياء الفرص الميتة)

## Context

**Phase:** 2 | **Priority:** Highest — Strategic bet #1  
**Duration:** ~1 week (assumes Agent #15 Compliance and Agent #3 Enrichment are ready)  
**Dependencies:** Agent #15 (Compliance Guardrail), Agent #3 (Waterfall Enrichment)  
**Module name:** `era_crm_dead_lead_resurrection`  
**Path:** `submodules/era_share_latest/era_crm_dead_lead_resurrection/`

## Business Value

Hundreds of lost/frozen leads in `crm.lead` = paid-for pipeline sitting idle. This is the #1 revenue recovery play for the Saudi market. No foreign SaaS tool does this well for Arabic + local objections.

## What This Agent Does

1. **Daily scan** of lost/frozen opportunities in `crm.lead` — classifies each by `crm.lost.reason`
2. **Detects new re-engagement signals:**
   - Competitor deal fell through (slow close by another company)
   - New product/price that addresses the original objection
   - Sufficient time elapsed (cooling period passed)
3. **Drafts an Arabic comeback message** using an approved template — only the personalized sections are generated by AI
4. **Sends the draft to the assigned salesperson** for review and approval before sending via WhatsApp (human-in-the-loop)

## Technical Requirements

### Odoo Models

```python
# New model: era.dead.lead.scan
class DeadLeadScan(models.Model):
    _name = 'era.dead.lead.scan'
    _description = 'Dead Lead Resurrection Scan Result'

    lead_id = fields.Many2one('crm.lead', required=True)
    lost_reason_id = fields.Many2one('crm.lost.reason')
    signal_type = fields.Selection([
        ('competitor_fell', 'Competitor Deal Fell Through'),
        ('new_product', 'New Product/Price Available'),
        ('cooling_passed', 'Cooling Period Passed'),
        ('activity_detected', 'New Activity Detected'),
    ])
    signal_score = fields.Float('Re-engagement Score', digits=(3, 2))
    draft_message = fields.Text('Draft Arabic Message')
    status = fields.Selection([
        ('pending', 'Pending Review'),
        ('approved', 'Approved'),
        ('sent', 'Sent'),
        ('rejected', 'Rejected'),
    ], default='pending')
    salesperson_id = fields.Many2one('res.users')
    reviewed_at = fields.Datetime()
    sent_at = fields.Datetime()
```

### Cron Job

- **Name:** `Dead Lead Resurrection — Daily Scan`
- **Interval:** Every 24 hours (off-peak, e.g., 6 AM AST)
- **Action:** Scan `crm.lead` where `active=False` or `stage_id` is lost, with `write_date` older than configurable cooling period

### LLM Integration

- **Model routing:** Use cheap model (GPT-4o-mini / Haiku) for signal detection. Use advanced model (Claude / GPT-4o) for Arabic message drafting only.
- **Prompt structure:**
  ```
  System: You are a Saudi B2B sales re-engagement specialist.
  You write formal but warm Arabic messages for re-engaging lost prospects.
  Use the template provided. Only fill in the personalized sections.
  Never invent facts. Respect cultural norms (greetings, titles).

  User: [Template + Lead data + Lost reason + Signal detected]
  ```
- **API key:** From `process.env` / Odoo system parameters — never hardcode.
- **Cost cap:** Max 500 LLM calls/day configurable via system parameter.

### WhatsApp (waha) Integration

- Send approved messages via existing `waha` integration
- Must pass through Agent #15 Compliance check before any send
- Track delivery status back to the scan record

### UI Components

1. **Kanban view** for `era.dead.lead.scan` — columns: Pending → Approved → Sent → Rejected
2. **Action button** on `crm.lead` form: "Check Resurrection Signals"
3. **Dashboard widget:** Weekly resurrection stats (scanned / approved / sent / replied)

### Configuration (System Parameters)

| Key | Default | Description |
|-----|---------|-------------|
| `era.resurrection.cooling_days` | 90 | Min days since loss before scanning |
| `era.resurrection.daily_limit` | 200 | Max leads to scan per day |
| `era.resurrection.llm_model_signal` | `gpt-4o-mini` | Model for signal detection |
| `era.resurrection.llm_model_draft` | `claude-sonnet-4-6` | Model for Arabic message drafting |
| `era.resurrection.auto_approve` | `False` | If True, skip human review (NOT recommended) |

## Security & Compliance

- Agent operates under salesperson's `res.users` permissions — never superuser
- All sends gated by Agent #15 Compliance (PDPL consent check)
- Every action (scan, draft, approve, send, reject) logged to critical event log (Rule 20)
- No API keys in code — `process.env` only (Rule 03)
- Hard cost cap on LLM calls (Rule 14)
