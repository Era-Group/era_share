قاعدة وكلاء الذكاء الاصطناعي — Base

هي «غرفة التحكّم» المشتركة لكل وكلاء الذكاء الاصطناعي في النظام: تجمع التكلفة والحدود، وسجلّ التدقيق، وطابور الموافقات البشرية، وطبقات حماية البيانات (PDPL) في مكان واحد — لا تُرسل رسائل بنفسها، بل تحرس وتراقب كل وكيل آخر.

الإصدار 19.0.6.0.0 · دليل المستخدم

وش يسوّي لك هذا الموديول؟ (بسطرين)

هذا الموديول هو الأساس الذي يُبنى عليه كل وكيل ذكاء اصطناعي آخر (إحياء العملاء، الإثراء، توليد العملاء...). لوحده لا «يفعل» شيئاً ظاهراً للعميل، لكنه يوفّر لك أربعة أشياء تهمّك مباشرة: سقف للتكلفة حتى لا تتفاجأ بفاتورة، طابور موافقات فلا يخرج شيء للعميل دون قرار إنسان، سجل تدقيق يحفظ كل قرار حسّاس، وحماية بيانات تمنع تسريب بيانات عملائك للذكاء الاصطناعي. كل الوكلاء الآخرين يمرّون من هنا.

١) ما هو الموديول ومن يستخدمه

باختصار عملي قبل التفاصيل.

«القاعدة» ليست وكيلاً يعمل عملاً، بل بنية مشتركة يعتمد عليها كل وكلاء الذكاء الاصطناعي. تخيّلها لوحة قيادة السيارة: لا تقود بدلاً عنك، لكنها تُظهر لك السرعة والوقود وتحذّرك قبل المشاكل. فائدتها أنها تجعل كل الوكلاء آمنين، خاضعين لميزانية، وقابلين للمراجعة من مكان واحد بدل تكرار ذلك في كل وكيل.

٢) خمسة مفاهيم تفهمها مرة واحدة

هذه المصطلحات تتكرّر في كل الشاشات؛ بعد فهمها يصبح كل شيء واضحاً.

الوكيل Agent

وش هوبرنامج صغير متخصّص بمهمة واحدة (مثلاً: إحياء العملاء المفقودين). كل وكيل يسجّل نفسه في قائمة Agents تلقائياً عند تركيب موديوله.
ليش يهمكهنا ترى كل وكلائك في مكان واحد، وحالة كلٍّ منهم وتكلفته.

طريقة الاتصال Transport

وش هوكيف يصل الوكيل للذكاء الاصطناعي. خياران: API = عبر الذكاء الاصطناعي المدمج في أودو (OpenAI / Google)، وCLI = عبر اشتراك Claude.
ليش يهمكيحدّد كيف تُحسب التكلفة: مسار API له تكلفة بالدولار لكل نداء، ومسار CLI بلا تكلفة دولارية (اشتراك ثابت) ويُحكَم بعدد «الرموز» بدلاً من المال.
الأثرلهذا ترى في اللوحة عمودين: «الرموز» و«التكلفة». وكيل CLI تكلفته الدولارية = 0، وهذا لا يعني أنه مجاني؛ استهلاكه يُقاس بالرموز.

الرمز Token

وش هووحدة قياس كمية النص التي يعالجها الذكاء الاصطناعي (تقريباً كلمة قصيرة ≈ رمز أو رمزان).
ليش يهمكهو «عدّاد الاستهلاك». الأرقام عندنا تقديرية (تقريباً رمز لكل 4 أحرف) — ميزانية تشغيلية للتحكّم، وليست فاتورة محاسبية دقيقة.

حالة الوكيل State

وش هووضع الوكيل الحالي، يظهر كشارة ملوّنة: enabled مُفعَّل paused موقوف capped بلغ الحد
ليش يهمكمُفعَّل: يعمل طبيعياً. موقوف: أوقفه مدير يدوياً. بلغ الحد: أوقفه النظام تلقائياً لأنه تجاوز حد الشهر — ويعود للعمل تلقائياً مع بداية الشهر التالي عندما ينخفض استهلاكه.

سجل التدقيق Audit Log

وش هودفتر «للقراءة فقط» يُسجَّل فيه كل قرار حسّاس (نداء ذكاء اصطناعي، منع، إرسال، طلب موافقة، تعطيل طبقة حماية...).
ليش يهمكهو مرجعك عند أي سؤال «من فعل ماذا ومتى؟». لا يمكن تعديله ولا حذفه — حتى تبقى المراجعة موثوقة (القاعدة 20).

٣) للمدير: الإعداد خطوة بخطوة

كل ما يلي يظهر فقط لمن لديه صلاحية «مدير وكلاء الذكاء الاصطناعي» (AI Agents Manager). الإعدادات الافتراضية آمنة — كلها مفعّلة — وقد تكتفي بها.

أ) طبقات الحماية والتحكّم (الإعدادات الرئيسية)

تفتحها من إعدادات أودو العامة، وليس من قائمة الوكلاء:

Settings (الإعدادات) ← CRM AI Agents

تجد ثلاث مجموعات:

سقف تكلفة الذكاء الاصطناعي AI Cost Cap (Rule 14)

وش هويفرض حداً أقصى للإنفاق الشهري قبل أن يُصرف أي مبلغ على مسار API.
ليش يهمكحمايتك من فاتورة مفاجئة: عند بلوغ الحد يتوقّف الوكيل تلقائياً (حالة capped).
الأثرمفعّل افتراضياً. قيمة السقف نفسها (افتراضياً 100 دولار شهرياً) تُضبط في «معاملات النظام» — انظر صندوق المدير التقني أسفل هذا القسم.

سجل التدقيق التفصيلي Detailed Audit Log (Rule 20)

وش هويكتب قيداً في سجل التدقيق لكل نداء وقرار ذكاء اصطناعي.
ليش يهمكيمنحك أثراً كاملاً قابلاً للمراجعة. يُنصَح بإبقائه مفعّلاً دائماً.
الأثرمفعّل افتراضياً.

منع النماذج بلا سعر Block Unpriced Models

وش هويمنع أي نداء على مسار API يستخدم نموذجاً ليس له سعر مُسجَّل في «بطاقة الأسعار».
ليش يهمكحتى لا تُصرف تكلفة «غير محسوبة» بصمت ويتسرّب الإنفاق خارج السقف.
الأثرمفعّل افتراضياً. إن استخدم وكيل نموذجاً جديداً، أضف سعره في «النماذج» أولاً (انظر القسم 4).

إخفاء البيانات الشخصية PII Redaction (PDPL)

وش هويُخفي البيانات الشخصية (اسم/هاتف/بريد...) قبل إرسال النص لأي مزوّد ذكاء اصطناعي خارجي، ويعيدها في الرد.
ليش يهمكالتزام بنظام حماية البيانات السعودي (PDPL): لا تغادر بيانات عميلك إلى الخارج بصيغتها الصريحة.
الأثرمفعّل افتراضياً. إطفاؤه يرسل بيانات شخصية للخارج دون حماية ويُسجَّل في سجل التدقيق باسم من أطفأه ومتى.

التحقق من الموافقة Consent Check (PDPL)

وش هويمنع أي نداء ذكاء اصطناعي يحمل بيانات عميل ما لم يكن العميل قد وافق على المعالجة الدولية لبياناته.
ليش يهمكيضمن أنك لا تعالج بيانات عميل دون إذنه.
الأثرمفعّل افتراضياً. إطفاؤه يُسجَّل في سجل التدقيق. (موافقة العميل تُسجَّل في بطاقته — انظر القسم 5.)

هوية تشغيل الوكلاء التلقائي Agent cron execution identity

وش هوباسم أي مستخدم تعمل المهام المجدولة لكل الوكلاء. خياران: مستخدم داخلي تختاره أنت (مُوصى به)، أو OdooBot (المستخدم الجذري).
ليش يهمكالمستخدم المحدّد الصلاحية يضمن أن الوكلاء التلقائية لا تتجاوز صلاحيات الوصول (القاعدة 09). OdooBot يتجاوز كل الصلاحيات وفيه خطر على الخصوصية.
الأثرالافتراضي هو مستخدم محدود الصلاحية اسمه CRM AI Automation يُنشأ تلقائياً. اتركه كما هو، أو وجّهه لمستخدم داخلي قائم لديك. تجنّب OdooBot إلا إن قبلت المخاطرة صراحةً.
عند إطفاء أي طبقة امتثال (إخفاء البيانات / الموافقة) أنت ترسل بيانات شخصية لمزوّد ذكاء اصطناعي غير سعودي دون حماية PDPL. كل تغيير من هذا النوع يُكتب في سجل التدقيق (من ومتى). لا تُطفئها إلا بقرار واعٍ وموثَّق.

ب) أسعار النماذج (بطاقة الأسعار)

CRM AI Agent Base ← Configuration ← Models

هذه ليست قائمة النماذج المتاحة (أودو يملكها)، بل جدول أسعار يربط كل نموذج بسعره لكل 1000 رمز، حتى يُحسب سقف التكلفة بدقة. مُهيّأ مسبقاً بأسعار GPT و Gemini. راجع الأسعار إذا غيّر المزوّد أسعاره أو أضاف أودو نموذجاً جديداً.

للمدير التقني: قيمة السقف وحدوده

واجهة الإعدادات فيها مفاتيح تشغيل/إيقاف فقط، أمّا قيمة السقف فتُضبط في معاملات النظام:

Settings ← Technical ← System Parameters

• سقف الدولار الشهري (مسار API): era_crm_ai_agents.monthly_cost_cap — الافتراضي 100 دولار.
• حدّ الرموز الشهري (مسار CLI): era_crm_ai_agents.monthly_token_limit — الافتراضي 2,000,000.
• سقف خاص بوكيل واحد: أضف معاملاً باسم era_crm_ai_agents.monthly_cost_cap.<tech_name> أو ...monthly_token_limit.<tech_name>.

تُراجَع الحدود يومياً بمهمة مجدولة (CRM AI Agents: Check cost caps) تنقل الوكيل تلقائياً بين enabled وcapped حسب استهلاكه.

٤) الشاشات شاشةً بشاشة

كل القوائم تحت تطبيق CRM AI Agent Base. الواجهة تُعرض بالعربية إذا كانت لغتك عربية (شُحنت ترجمة عربية كاملة)؛ ونضع بجانب كل اسم تسميته الإنجليزية ليسهل التعرّف عليه أياً كانت لغتك.

الوكلاء Agents

CRM AI Agent Base ← Agents

القائمة الكاملة للوكلاء المُسجَّلين. المندوب يقرأ فقط؛ المدير يفتح بطاقة الوكيل ويستطيع إيقافه أو تفعيله بزرّي Pause / Enable أعلى البطاقة. أهم الحقول في البطاقة:

الاعتمادات Approvals

CRM AI Agent Base ← Approvals — الطابور المشترك لكل الوكلاء المُرسِلة.

يعرض افتراضياً ما هو معلّق (بانتظار قرارك) فقط. كل سطر هو مُخرَج ذكاء اصطناعي ينتظر موافقة إنسان (مثل رسالة عربية قبل إرسالها). الأعمدة: التاريخ، الوكيل، السجل المرتبط Record، المراجِع، الحالة، وتاريخ القرار. عند فتح السطر:

  1. اقرأ المحتوى المقترح Proposed Content (للقراءة فقط).
  2. عدّل عند الحاجة في حقل Edited Content — النص المُعدَّل هو ما يُعتمد ويُرسَل (يَجُبّ المقترح). اتركه فارغاً للموافقة على المقترح كما هو.
  3. اضغط Approve للاعتماد (ينفّذ الوكيل الإجراء)، أو Reject للرفض (لا يحدث شيء).
فلتر مفيد استخدم My Queue لرؤية ما هو موجَّه إليك أنت فقط. كل قرار (موافقة/رفض) يُسجَّل في سجل التدقيق.

الإعداد ← الاستهلاك Usage

CRM AI Agent Base ← Configuration ← Usage — للمدير، للقراءة فقط.

كل نداء ذكاء اصطناعي يترك سطراً هنا. مفيد لتتبّع من يستهلك وكم. الأعمدة: التاريخ، الوكيل، النموذج، رموز المدخلات/المخرجات/الإجمالي (مع مجاميع)، مصدر العدّ Token Source (مُقدَّر/مقيس)، علامة CLI، التكلفة، وعلامة «بلا سعر» Unpriced. هناك أيضاً عرض «محوري» Pivot (الوكيل × الشهر). فلاتر جاهزة: هذا الشهر، CLI، API المُسعَّر، بلا سعر.

الموافقة على المعالجة الدولية AI Int'l Processing Consent

وش هومفتاح تؤكّد به أن هذا العميل وافق على معالجة بياناته عبر مزوّد ذكاء اصطناعي دولي.
ليش يهمكإذا كانت طبقة «التحقق من الموافقة» مفعّلة (وهي كذلك افتراضياً)، فلن تعالج الوكلاء بيانات هذا العميل ما لم تُفعّل هذا المفتاح.
الأثربمجرد تفعيله يظهر حقل AI Consent Date (تاريخ الموافقة) تلقائياً. هذا ما يقرأه الحارس قبل كل نداء.

٦) كيف تجرّبه بنفسك خطوة بخطوة

جرّبة عملية على تركيب نظيف — كلها خطوات تقدر تسوّيها بنفسك بدون أدوات تقنية. (الخطوات 1–5 تعمل على «القاعدة وحدها»؛ الخطوة 6 تُظهر النظام كاملاً.)

  1. تأكّد أن القوائم ظهرت.
    افتح تطبيق CRM AI Agent Base. كمدير ترى: Dashboard · Agents · Approvals · Configuration. كمندوب ترى الثلاثة الأولى فقط. (إن لم تظهر القوائم، فصلاحيتك ليست ضمن مجموعة الوكلاء — اطلب من المدير إضافتك.)
  2. افحص بطاقة الأسعار.
    Configuration ← Models. يجب أن ترى صفوفاً مُهيّأة مسبقاً مثل gpt-4.1-mini، gpt-4o، gemini-2.5-flash، gemini-2.5-pro مع أسعارها. وجودها يعني أن سقف التكلفة جاهز للحساب.
  3. افتح الإعدادات وتأكّد أن الحماية مفعّلة.
    Settings ← CRM AI Agents. الخمسة مفاتيح يجب أن تكون مفعّلة، وهوية التشغيل = CRM AI Automation.
  4. جرّب أن سجل التدقيق يعمل فعلاً (اختبار ملموس).
    في نفس شاشة الإعدادات، أطفئ مؤقتاً مفتاح Consent Check ثم احفظ. الآن افتح Configuration ← Audit Log وستجد قيداً جديداً نوعه compliance_disabled باسمك ووقت التغيير. أعِد تفعيل المفتاح بعد التجربة. هذا يثبت لك أن طبقة التدقيق حيّة.
  5. سجّل موافقة عميل تجريبي.
    افتح أي عميل في Contacts ← تبويب AI & PDPL ← فعّل AI Int'l Processing Consent ← احفظ. لاحظ ظهور تاريخ الموافقة تلقائياً.
  6. شغّل النظام كاملاً (اختياري لكنه الأوضح).
    ثبّت أحد وكلاء العمل (مثل Enrichment أو Dead-Lead Resurrection) ثم ارجع هنا: سيظهر الوكيل تلقائياً في Agents وDashboard. شغّله، وستمتلئ Usage بأسطر استهلاك، وAudit Log بقيود، و(لوكيل مُرسِل) Approvals برسائل تنتظر موافقتك.
النتيجة المتوقّعة على «القاعدة وحدها»: القوائم تظهر، بطاقة الأسعار مليئة، الإعدادات مفعّلة، وسجل التدقيق يلتقط تغييراتك. لوحة المعلومات والوكلاء فارغة حتى تثبّت أول وكيل — وهذا هو السلوك الصحيح.

٧) ملاحظات وحدود مهمة (بصدق)

حتى لا يُفهم أكثر مما هو موجود فعلاً.

  • القاعدة لا «تفعل» شيئاً ظاهراً وحدها. هي بنية تحتية؛ القيمة تظهر عند تثبيت وكيل فعلي. لوحة فارغة على تركيب نظيف = أمر طبيعي.
  • أرقام الرموز تقديرية. تُحسب بالطول (تقريباً رمز لكل 4 أحرف) لأن المزوّد لا يُرجِع عدّاً دقيقاً عند هذه النقطة — فاعتبرها ميزانية تشغيلية للتحكّم، لا فاتورة محاسبية.
  • قيمة السقف ليست في شاشة الإعدادات. الإعدادات فيها مفاتيح فقط؛ القيمة (100 دولار / 2 مليون رمز افتراضياً) في «معاملات النظام» — انظر صندوق المدير التقني.
  • المهمة المجدولة الجديدة قد تحتاج إعادة تشغيل الخادم لتُسجَّل بعد التركيب (ملاحظة تشغيلية لمسؤول النظام).
  • طبقة إخفاء البيانات تستهدف الصيغ الشائعة للأسماء والهواتف والبريد والهوية؛ ابقِها مفعّلة دائماً، ولا تعتمد إطفاءها كحلّ.

٨) أسئلة شائعة قصيرة

لماذا لوحة المعلومات وقائمة الوكلاء فارغة؟
لأنك ثبّت «القاعدة» فقط ولم تثبّت أي وكيل بعد. كل وكيل يسجّل نفسه تلقائياً عند تركيبه.

ما الفرق بين «موقوف» و«بلغ الحد»؟
paused = أوقفه مدير يدوياً. capped = أوقفه النظام تلقائياً لتجاوزه حدّ الشهر، ويعود وحده مع الشهر الجديد.

وكيل CLI تكلفته صفر — هل يعني أنه مجاني؟
لا. مسار CLI لا تكلفة دولارية لكل نداء (اشتراك ثابت)، لكنه يستهلك «رموزاً» يُحكَم بها عبر حدّ الرموز. راقب عمود الرموز.

عدّلت نص رسالة في الاعتمادات — أيّهما يُعتمد؟
النص المُعدَّل (Edited Content) هو الذي يُعتمد ويُرسل؛ يَجُبّ المقترح. اتركه فارغاً للموافقة على المقترح كما هو.

لماذا مُنِع نداء ذكاء اصطناعي؟
افتح سجل التدقيق وابحث عن حدث blocked؛ السبب عادةً: العميل لم يوافق (PDPL)، أو بلغ الوكيل سقفه، أو النموذج بلا سعر في بطاقة الأسعار.

لماذا لا أرى قائمة «الإعداد» (Configuration)؟
لأنها للمدير فقط (AI Agents Manager). المندوب يرى لوحة المعلومات والوكلاء والاعتمادات فقط.

كيف أمنع معالجة بيانات عميل معيّن نهائياً؟
لا تفعّل «الموافقة على المعالجة الدولية» في بطاقته (تبويب AI & PDPL). مع بقاء «التحقق من الموافقة» مفعّلاً، لن تعالج الوكلاء بياناته.
