# موديول إدارة نجاح العملاء — التوثيق الكامل للمميزات
## Era Customer Success — `era_customer_success`

> موديول لأودو 19 Enterprise يوفّر منصة موحّدة لمتابعة العملاء الحاليين، إسناد كل عميل لمهندس نجاح عملاء (CSM)، وعرض كل ما يجري مع العميل في مكان واحد، بالإضافة إلى لوحة مدير لتقييم الأداء ومستوى المتابعة.

---

## 1. الفكرة والمعمارية

الموديول **طبقة تنسيق (Orchestration Layer)** فوق ما هو موجود في النظام، ولا يُكرّر أي وظيفة قائمة:

| الوظيفة | المصدر المُعاد استخدامه |
|---|---|
| التذاكر ووقت الحل وSLA | `helpdesk.ticket` (الحقول `close_hours`, `sla_fail`) |
| رضا العملاء (CSAT) | `rating.rating` |
| الاستبيانات (NPS/CSAT) | `survey.user_input` (الحقل `scoring_percentage`) |
| الاشتراكات وMRR والتجديد والـChurn | `sale.order` (حالات `3_progress`/`4_paused`/`6_churn`) |
| التحصيلات والمتأخرات | `account_followup` (`total_overdue`, `followup_status`) |
| المكالمات + تلخيص ✦ | `voip.call` (+ `era_voip_ext`) |
| الواتساب | `whatsapp` (Meta الأصلي) |
| الرسائل النصية | مُركّب الرسائل `sms.composer` |
| الفرص والتوسّع (Upsell) | `crm.lead` |
| الأنشطة والكادينس | `mail.activity` + `mail.activity.plan` |

**ما الجديد فعلاً؟** نموذج مركزي `cs.account`، مراحل دورة الحياة `cs.stage`، العروض `csm.offering`، لقطات المؤشرات `csm.kpi.snapshot`، معالج التقاط الطلبات، طبقة التايملاين الموحّد، الـHealth Score، والصلاحيات.

## 2. السجل المركزي: حساب نجاح العميل (`cs.account`)

سجل واحد لكل **شركة عميل** (`partner_id` لشركة، فريد لا يتكرر). يرث `mail.thread` و`mail.activity.mixin` (شاتر + أنشطة). يجمّع تلقائياً كل جهات اتصال الشركة وأبنائها (`child_of`).

### أهم الحقول

| الحقل | النوع | الوصف |
|---|---|---|
| `partner_id` | Many2one | الشركة العميلة (فريد) |
| `csm_user_id` | Many2one | مهندس نجاح العملاء المسؤول |
| `team_id` | Many2one `crm.team` | فريق نجاح العملاء |
| `tier` | Selection | التصنيف: استراتيجي / نمو / أساسي / طويل الذيل |
| `cadence` | Selection | إيقاع المتابعة: أسبوعي / كل أسبوعين / شهري / ربع سنوي |
| `lifecycle_stage_id` | Many2one `cs.stage` | مرحلة دورة الحياة (كانبان) |
| `onboarding_start_date` | Date | تاريخ بدء التهيئة (مرجع 30-60-90) |
| `health_score` | Integer 0–100 | مؤشر الصحة المحسوب |
| `health_status` | Selection | جيد / مراقبة / خطر / حرِج |
| `churn_risk` | Boolean | معرّض للفقدان |
| `usage_signal` | Selection | مستوى استخدام النظام: نشط / منخفض / متوقف |
| `mrr` | Monetary | الإيراد الشهري المتكرر (من الاشتراكات النشطة) |
| `renewal_date` / `days_to_renewal` | Date / Integer | أقرب تجديد وعدد الأيام المتبقية |
| `subscription_churned` | Boolean | فُقد الاشتراك |
| `open_tickets_count` / `sla_failed_count` | Integer | تذاكر مفتوحة / تذاكر تجاوزت SLA |
| `avg_resolution_hours` | Float | متوسط وقت حل التذاكر (ساعات عمل) |
| `csat_latest` | Float 1–5 | آخر تقييم رضا |
| `nps_latest` | Float % | آخر نتيجة استبيان |
| `overdue_amount` / `followup_status` | related | المتأخرات وحالة التحصيل (من `account_followup`) |
| `opportunity_count` / `upsell_revenue` | Integer / Monetary | الفرص وإيراد التوسّع المكسوب |
| `last_touch_date` / `next_touch_date` | Datetime / Date | آخر تواصل / المتابعة القادمة المجدولة |
| `meeting_count` | Integer | عدد الاجتماعات |
| `call_count` / `whatsapp_count` | Integer | عدد المكالمات / رسائل الواتساب |

> كل المقاييس تُحدَّث عبر مهمة مجدولة ليلية (cron) وعبر زر **"إعادة الحساب"**، فتُقرأ من الحقول المخزّنة (أداء سريع) بدل الاستعلام الحي.

## 3. إسناد العميل للمهندس (Assignment)

- حقل واحد `csm_user_id` = المهندس المسؤول. القيد الفريد على `partner_id` يضمن عميل واحد = حساب واحد = مهندس واحد.
- **المزامنة التلقائية:** عند تعيين/تغيير المهندس، يُكتب نفس المستخدم في `partner_id.user_id` و`followup_responsible_id`، فترث فلاتر "عملائي" في الـCRM وتذكيرات التحصيل صاحب المسؤولية تلقائياً.
- **التوزيع التلقائي (Load Balancing):** زر **"Auto-assign CSM"** / الدالة `_least_loaded_csm` تختار المهندس الأقل حِملاً (أقل عدد حسابات غير مفقودة) — نفس منطق التوزيع المتوازن في الـHelpdesk.
- **النقل/التسليم:** عند مغادرة مهندس، يُعاد الإسناد عبر تغيير `csm_user_id` (يمكن ربطه بمعالج إعادة الإسناد `era.emp.reassign.wizard` الموجود).

## 4. مؤشر صحة العميل (Health Score)

عدد مخزّن 0–100 يُعاد حسابه ليلياً، مجموع مرجّح لستة عناصر فرعية (كلٌّ 0–100):

| العنصر | الوزن | القاعدة |
|---|---|---|
| الدعم | 20% | 100 − 15×(تذاكر مفتوحة) − 20×(تذاكر SLA فاشلة) |
| التحصيل | 15% | 100 إن لا متأخرات، وإلا تتناقص بنسبة المتأخرات إلى MRR |
| حداثة التواصل | 15% | ≤7 أيام=100، ≤14=80، ≤30=60، ≤60=30، وإلا 0 |
| الرضا (CSAT/NPS) | 20% | مزيج من آخر CSAT (1–5) وآخر نتيجة استبيان % |
| قرب التجديد | 15% | >90 يوم=100، 30–90=70، 7–30=40، <7=20، متأخر=0 |
| الاستخدام | 15% | نشط=100، منخفض=50، متوقف=0 |

> **تحليل المشاعر بـ ✦ (عنصر سابع — اختياري):** عند تفعيل `AI Sentiment Analysis` من الإعدادات، يُحلّل `ai.agent` نص تذاكر العميل ويعطي درجة مشاعر (−100..100). تُجمَّع تذاكر آخر 90 يوماً بوزن **أُسّي** (الأحدث أوزن، نصف عمر 90 يوماً) في `sentiment_score`/`sentiment_label` على الحساب، وتدخل في معادلة الصحة بوزن 15%. كما أن عنصر "حداثة التواصل" صار اضمحلالاً أُسّياً سلساً بدل الشرائح. والمشاعر **السلبية** على أي تذكرة تُطلق تلقائياً نشاط "Service Recovery" للمهندس وتنبيهاً في التايملاين.
>
> الأوزان الافتراضية (7 عناصر): دعم 18% · تحصيل 12% · حداثة 13% · رضا 17% · تجديد 12% · استخدام 13% · مشاعر 15%.

**النطاقات:** `≥75 جيد` · `55–74 مراقبة` · `40–54 خطر` · `<40 حرِج`.
`churn_risk = (الدرجة < 40) أو (فُقد الاشتراك)`.

> الأوزان قابلة للتعديل دون برمجة عبر `ir.config_parameter` بالمفاتيح:
> `era_customer_success.weight_support`, `weight_collections`, `weight_recency`, `weight_satisfaction`, `weight_renewal`, `weight_usage`.

## 5. دورة الحياة 30-60-90 (`cs.stage`)

مراحل افتراضية تُعرض ككانبان:

| المرحلة | النافذة الزمنية | ملاحظة |
|---|---|---|
| Onboarding (0-30) | 0–30 يوم | الفهم والتهيئة والتأكد من الاستخدام |
| Engage (30-60) | 30–60 يوم | اجتماعات دورية وتبنّي وإغلاق طلبات الدعم |
| Grow (60-90) | 60–90 يوم | مراجعة أعمال، اكتشاف فرص توسّع، مسار التجديد |
| Steady | 90+ | عميل مستقر بإيقاع أسبوعي/شهري |
| At Risk | — | الصحة انخفضت → تدخّل |
| Churned | — | عميل مفقود (مطوي في الكانبان) |

**الأتمتة:** مهمة يومية تُرقّي حسابات الـOnboarding حسب الأيام المنقضية من `onboarding_start_date`، وتنقل الحسابات المعرّضة للخطر إلى **At Risk** وتجدول لها نشاط تدخّل. خطة الأنشطة **"CS Onboarding 30-60-90"** (`mail.activity.plan`) قابلة للإطلاق من ودجت الأنشطة على الحساب (نقطة 0 / 14 / 30 / 60 / 90 يوم).

## 6. منصة العميل 360 (الشاشة الموحّدة)

### أ) أزرار المتابعة السريعة (في الـHeader)

| الزر | الإجراء |
|---|---|
| **WhatsApp** | يفتح محادثات الواتساب الأصلية (Meta) للعميل |
| **SMS** | يفتح مُركّب الرسائل النصية موجّهاً للعميل |
| **Log Call** | يجدول نشاط مكالمة لليوم ويسجّل ملاحظة (والاتصال الفعلي عبر ودجت الهاتف/السوفت فون) |
| **Meeting** | يفتح إنشاء اجتماع `calendar.event` مع العميل |
| **Schedule Follow-up** | يجدول نشاط متابعة للمهندس |
| **Present Offering** | ينشئ عرضاً جديداً (`csm.offering`) |
| **Capture Request** | يفتح معالج التقاط طلب (دعم/توسّع/تجديد) |
| **Recompute** | (للمدير) يعيد حساب المقاييس والصحة |

### ب) الأزرار الذكية (Smart Buttons)
تذاكر مفتوحة · اشتراكات · فواتير/متأخرات · فرص · مكالمات · واتساب · اجتماعات · استبيانات · مشاريع · عروض — كل زر يفتح القائمة المفلترة على العميل وأبنائه.

### ج) التايملاين الموحّد
الشاتر الأصلي (`mail.thread`) هو العمود الفقري؛ يجمع تلقائياً: الإيميل، الملاحظات، الـSMS، واتساب Meta، والأنشطة. وتُضاف القنوات المسجّلة في نماذج منفصلة عبر **مهمة مزامنة (cron) كل ساعة** تنشر سطراً في تايملاين الحساب لكل:
- 📞 **مكالمة VoIP** (مع المدة وملخص ✦) — نوع فرعي `mt_cs_call`
- 🎫 **إغلاق تذكرة** (مع وقت الحل) — نوع فرعي `mt_cs_ticket`
- 📊 **رد استبيان** (مع النتيجة، وجدولة "Service Recovery" إذا كانت منخفضة) — نوع فرعي `mt_cs_survey`

> المزامنة **idempotent** عبر الحقل `cs_timeline_synced` المضاف لكل من `voip.call`, `helpdesk.ticket`, `survey.user_input` — فلا تتكرر السطور.
> **فلترة القنوات:** الأنواع الفرعية تتيح إظهار "المكالمات فقط" أو "الواتساب فقط" من فلتر الشاتر.

## 7. العروض (`csm.offering`)

تسجيل ما يُعرض على العميل من منتجات/خدمات جديدة:
- الحقول: `partner_id`, `csm_user_id`, `product_tmpl_ids`, `expected_value`, `channel`, `state` (مسودة/مُقدّم/مقبول/مرفوض).
- **عند القبول:** زر "Accept → Create Opportunity" يُنشئ `crm.lead` فرصة موسومة **CS Upsell** بنوع توسّع، ويربطها بالعرض — فتغذّي مؤشر إيراد التوسّع.

## 8. التقاط طلبات العميل (`cs.capture.request`)

معالج يوجّه أي طلب جديد إلى المكان الصحيح:
- **دعم** → ينشئ `helpdesk.ticket`.
- **توسّع/تجديد** → ينشئ `crm.lead` فرصة موسومة CS Upsell.
- في الحالتين يسجّل سطراً في تايملاين الحساب ويفتح السجل المُنشأ.

## 9. لوحة المدير والمؤشرات (KPIs)

### نموذج اللقطات `csm.kpi.snapshot`
مهمة مجدولة شهرية تبني صفاً لكل حساب/فترة بالمقاييس: الصحة، MRR، CSAT، NPS، التذاكر المفتوحة، متوسط وقت الحل، الاجتماعات، إيراد التوسّع، المتأخرات، أيام منذ آخر تواصل، حالة الفقدان، عميل نشط.

### ربط كل مؤشر بمصدره

| المؤشر | المصدر | الحساب |
|---|---|---|
| CSAT | `rating.rating` | متوسط التقييم |
| NPS / نتيجة الاستبيان | `survey.user_input.scoring_percentage` | متوسط النسبة |
| Retention / Churn | `sale.order` (حالات الاشتراك) | نشط بالنهاية ÷ نشط بالبداية / المفقود |
| معدل التجديد | `sale.order` | مُجدَّد ÷ (مُجدَّد + مفقود) |
| متوسط وقت الحل | `helpdesk.ticket.close_hours` | متوسط الساعات |
| عدد الاجتماعات | `calendar.event` + الأنشطة المنجزة | عدّ لكل مهندس |
| إيراد التوسّع | `crm.lead` (موسوم CS Upsell، مكسوب) | مجموع `expected_revenue` |

### اللوحات (Native أولاً)
- **Manager Dashboard:** عروض Graph/Pivot حية على `cs.account` مجمّعة حسب المهندس (متوسط الصحة، MRR، التذاكر، إيراد التوسّع).
- **KPIs:** Pivot/Graph/List على `csm.kpi.snapshot` (صفوف = المهندس، أعمدة = الشهر) للاتجاهات عبر الزمن وتصدير Excel.
- **تقييم المهندس / مستوى المتابعة:** المقارنة بين المهندسين عبر عدد الحسابات، متوسط صحة المحفظة، CSAT، الفقدان مقابل المحتفظ، والمتابعات المتأخرة.

> *(مرحلة لاحقة اختيارية: صفحة OWL تنفيذية ببطاقات KPI كبيرة على نمط `project_dashboard_odoo`.)*

## 13. تحديثات الإصدار 19.0.2.0.0 (الحزمة الصفراء + VoIP)

- **خيار VoIP في وسائل التواصل:** أُضيف حقلا `phone`/`email` على شاشة الحساب (قسم *Contact*) بأداة `widget="phone"`، فيظهر زر اتصال يبدأ مكالمة **VoIP مباشرة عبر السوفت فون** (click-to-dial) إلى جانب أزرار واتساب/SMS/تسجيل مكالمة.
- **لوحة المدير التنفيذية (OWL):** قائمة جديدة *Reporting ← Executive Dashboard* — شاشة واحدة ببطاقات KPI كبيرة قابلة للنقر (عدد العملاء، متوسط الصحة، المعرّضون للخطر، التجديدات <90 يوم، MRR، CSAT، المشاعر، إيراد التوسّع) + **ترتيب المهندسين** (قابل للنقر للتصفية) + قائمة **العملاء المعرّضين للخطر** (نقرة تفتح الحساب). مبنية بنمط `project_dashboard_odoo` (OWL + ORM، بلا CDN خارجي).
- **مؤشر المزاج (Sentiment Mood):** أيقونة مزاج (🙂/😐/🙁) على بطاقة الكانبان لكل عميل، وعلى أحداث التذاكر في التايملاين، حسب نتيجة تحليل المشاعر.
- **اتجاه المشاعر عبر الزمن:** قائمة *Reporting ← Sentiment Trend* — رسم خطي يقارن المشاعر وCSAT والصحة شهرياً.

## 14. مميزات ✦ (الإصدارات 19.0.3.x – 19.0.4.x)

> كل مميزات ✦ **اختيارية** وتعتمد على وحدة `ai` في أودو. **تتطلب إدخال مفتاح OpenAI** (الإعدادات ← AI ← OpenAI key) وتفعيل الخيار المناسب. وتتعامل بلطف عند غياب المفتاح فلا يتعطّل شيء.

### أ) الإجراء التالي الأنسب (Next Best Action)
لكل عميل، يقترح وكيل ✦ **الخطوة التالية** بناءً على **لقطة كاملة لوضعه + تاريخ عمله معنا + آخر اقتراح ومتى**:
- اللقطة تشمل: المدة معنا، المرحلة، الصحة، خطر الفقدان، MRR والتجديد، التذاكر وSLA، CSAT/NPS، المشاعر، التحصيل، الاستخدام، آخر التفاعلات، **والاقتراح السابق وتاريخه** (فلا يكرّره ويبني عليه).
- يُخزَّن الاقتراح الحالي على الحساب (الإجراء + السبب + الأولوية + الموعد + تاريخ التوليد) مع **سجل كامل للاقتراحات** (`cs.next.action`).
- يظهر كشريط أعلى شاشة العميل + زر **"Suggest Next Step (AI)"** + تبويب **سجل اقتراحات ✦** + يُنشر في التايملاين.
- مهمة يومية تولّده تلقائياً (الأسوأ صحةً أولاً). الخيار: `AI Next Best Action`.

### ب) كتالوج الخدمات (Service Catalog) — `cs.service`
قائمة **عروض نموذجية** قابلة لإعادة الاستخدام (قائمة *Customer Success ← Service Catalog*). كل خدمة: الاسم، الرابط، الوصف، المميزات/الفوائد، تفاصيل المنتج، ملاحظات دعم القرار، وصيغة عرض مقترحة. مُرفق مثال جاهز **"ربط مقيم"** (https://era.net.sa/hr-muqeem).

### ج) قراءة الخدمة من رابطها بـ ✦
زر **"Read from URL (AI)"** على الخدمة: يجلب صفحة الخدمة من الرابط، ويستخرج **بـ ✦** الوصف والمميزات وتفاصيل المنتج والفئة المستهدفة وملاحظات القرار وصيغة عرض مقترحة، ويملأ الحقول تلقائياً.

### د) صياغة عرض مخصّصة لوضع العميل
على العرض (`csm.offering`): اختر **خدمة من الكتالوج**، ثم زر **"Suggest Pitch (AI)"** يولّد **رسالة مخصّصة لوضع هذا العميل تحديداً** (من لقطة حالته) جاهزة للإرسال، تُحفظ في تبويب *Suggested Pitch*.

**وكلاء ✦ المُعرّفون:** `cs_sentiment_agent` (مشاعر التذاكر)، `cs_next_action_agent` (الإجراء التالي)، `cs_service_extract_agent` (استخراج الخدمة من الرابط)، `cs_offering_pitch_agent` (صياغة العرض).

## 15. ✦ التنبّؤي والإرشادي المتقدّم (الإصدارات 19.0.6.x – 19.0.13.x)

> نقلة من ✦ **وصفي** (يلخّص ويحلّل) إلى ✦ **تنبّؤي + إرشادي** (يتوقّع ويوجّه قبل وقوع المشكلة). كل ما يلي **اختياري** بمفتاح تفعيل، ويعمل بلطف بلا مفتاح OpenAI.

### أ) ملخص ذكي تحت اسم العميل (Profile Summary) — `cs_profile_summary_agent`
ملخص قصير (الوضع، النطاق، مجال العمل، مدة التعامل) يظهر تحت اسم العميل، يُولَّد تدريجياً بمهمة مجدولة. الخيار: `AI Profile Summary`.

### ب) متنبّئ احتمال الفقدان (Churn Forecaster) — `cs_churn_forecast_agent`
بدل علَم ثنائي، يعطي **احتمال فقدان % عند 30/60/90 يوماً + أهم الأسباب** بالعربية، مستنداً إلى لقطة الحالة + **تاريخ مؤشرات الحساب** (`_build_snapshot_trend` — أول استغلال للقطات الشهرية). **حاجز أمان برمجي** يرفع الخطر تلقائياً عند إشارات قوية (متأخرات > MRR، فشل SLA، صحة حرِجة، مشاعر سلبية) فلا يُخفيه رقم متفائل. مهمة يومية على كل العملاء النشطين؛ الاحتمال ≥60% ينقل العميل لمرحلة «معرّض للخطر». يظهر في الفورم والقائمة ومحور المدير. الخيار: `AI Churn Forecast`.

### ج) وكيل استراتيجية التجديد (Renewal Strategy) — `cs_renewal_strategy_agent`
للعملاء داخل **نافذة التجديد (≤90 يوماً)**: يحدّد **الرافعة المناسبة** (تحصيل أولاً / عرض أولاً / إعادة تفاعل / اعتيادي) + **توقّع التجديد** (مُرجَّح/معرّض/حرِج) + **خطوات مؤرّخة تنازلياً**. يجدول نشاط مكالمة للمهندس عند الخطر. الخيار: `AI Renewal Strategy`.

### د) مُحرِّر المتابعة/الردود (Follow-up Composer) — `cs_followup_draft_agent`
زر **«إنشاء رسالة (AI)»**: يصوغ رسالة **واتساب/SMS/إيميل** جاهزة بلغة العميل، حسب القناة والنبرة والغرض (أو رداً على آخر رسالة)، ثم يوجّهها للمُنشئ الأصلي للإرسال أو يسجّلها في التايملاين.

### هـ) الموجز التحضيري للمكالمة/الاجتماع (Pre-Call Briefing) — `cs_call_prep_agent`
زر **«تحضير (AI)»**: يولّد بطاقة تحضير من 4 أقسام (لمحة سريعة / نقاط للطرح / حساسيات ومخاطر / هدف المكالمة) من لقطة الحالة + المؤشرات + آخر التفاعلات.

### و) مساعد الحساب الذكي (Account Copilot) — `cs_account_qa_agent`
زر **«اسأل ✦»**: اطرح أي سؤال بلغة طبيعية عن العميل (الصحة، المخاطر، التجديد، الفرص…) فيجيب **مستنداً إلى بياناته وسجلّه الزمني ولقطاته** فقط، ويصرّح إن كانت المعلومة غير متوفرة.

### ز) الاقتراحات الأسبوعية (Weekly Suggestions) — `cs_worklist_agent` + `cs.weekly.suggestion`
**نموذج مُهيكَل**: سطر لكل عميل يحتاج اهتماماً هذا الأسبوع (الأولوية، السبب، **التوجيه**، الصحة/الفقدان، الحالة للتنفيذ/منجز).
- **صفحة المهندس «الاقتراحات الأسبوعية»**: تتكيّف بالدور — المهندس يرى اقتراحاته، **والمدير يرى كل اقتراحات كل المهندسين** للمتابعة (عبر قاعدة الوصول).
- **صفحة المدير «الاقتراحات الأسبوعية (الكل)»** (التقارير): مجمّعة حسب المهندس + زر **«ولّد الآن»**.
- تُجدَّد تلقائياً **كل سبت 07:00**. الخيار: `AI Weekly Worklist`.

### ح) جلب العملاء بـ ✦ (Smart Customer Import) — `cs_customer_classify_agent`
قائمة بالإعدادات (للمدير): تجلب العملاء ذوي التعامل السابق (تذاكر/مشاريع)، **تصنّفهم بـ ✦ إلى فئات**، وتسندهم عشوائياً للمهندسين المتاحين دون تكرار عميل موجود.

### تحسينات سلوكية مهمة
- **إعادة احتساب تلقائية:** مؤشرات الحساب تُحدَّث بعد **كل تعديل** (بلا ✦، فلا تكلفة) — لا حاجة لزر «إعادة الحساب» (أُخفِي).
- **أزرار النشاط في الشاتر:** «اجتماع» و«جدولة متابعة» تُستخدم من جدولة النشاط الأصلية في الشاتر (أُزيلت من الرأس).
- **عرض ✦ في الشاتر** بصيغة HTML سليمة (عريض/أسطر) عبر `Markup`.
- **تلميحات (Tooltip)** على كل زر رأس وزر ذكي.
- **الكرونات (12)** موزّعة على دقائق مختلفة لتفادي التشغيل المتزامن.
- **كاتلوج الخدمات:** للمدير إدارته؛ للمهندس **عرض قراءة فقط** (بطاقات/قائمة/فورم).

**إجمالي وكلاء ✦: 12.** خيارات التفعيل في *الإعدادات ← Customer Success ← Artificial Intelligence*.
