ERA Data Merge — Auto-Merge

دمج التكرارات التلقائي من ERA

A scheduled cron job that automatically processes confirmed duplicate groups from Odoo's Data Cleaning app — using only the built-in Odoo merge wizard, with configurable daily limits, dry-run simulation, and a full audit log.

مهمة مجدولة تدمج تلقائياً مجموعات التكرارات المؤكَّدة في تطبيق تنظيف البيانات — باستخدام معالج الدمج المدمج في أودو، مع حدود يومية قابلة للضبط ووضع محاكاة وسجل تدقيق كامل.

🔄

Automatic Merge Cron

Runs on a configurable schedule (default: daily at 2 AM via ir.cron). Reads all data_cleaning.record.group records in the to merge state and processes them in batches using Odoo's standard ORM merge logic. Zero manual work is required after the initial setup — the cron handles everything silently in the background without any user intervention.

مهمة الدمج التلقائية

تعمل على جدول قابل للتخصيص (الافتراضي: يومياً الساعة 2 صباحاً). تقرأ جميع سجلات data_cleaning.record.group في حالة "جاهز للدمج" وتعالجها دفعةً دفعة عبر منطق الدمج المعياري في أودو. لا يلزم أي تدخل يدوي بعد الإعداد الأولي.

🛡️

Production-Safe Design

Processes only groups that have been reviewed and confirmed by a human — never blindly merges raw auto-detections. The batch size is capped by the system parameter era_data_merge.batch_size (default 20) to prevent long-running database transactions that could lock tables. Only groups with state = 'to_merge' are touched; unreviewed detections are skipped.

تصميم آمن للإنتاج

يعالج فقط المجموعات التي راجعها إنسان وأكّدها — لا يدمج الاكتشافات التلقائية الخام أبداً. حجم الدفعة محدود بمعامل النظام era_data_merge.batch_size (الافتراضي 20) لمنع المعاملات الطويلة التي قد تقفل الجداول. تُتجاهل الاكتشافات غير المراجعة.

🔍

Dry-Run Mode

Set the system parameter era_data_merge.dry_run = True under Settings → Technical → Parameters → System Parameters to simulate the run. The cron logs exactly what it would merge — group IDs, record counts, destination record — without touching any data. Ideal for validating configuration before going live in production or after schema changes.

وضع المحاكاة

اضبط era_data_merge.dry_run = True في معاملات النظام لتشغيل المحاكاة. تُسجّل المهمة ما ستدمجه تحديداً — معرّفات المجموعات، عدد السجلات، السجل الوجهة — دون المساس بأي بيانات. مثالي للتحقق من الإعداد قبل بدء الإنتاج.

📊

Full Audit Log

Every merge attempt — success or failure — is written to a dedicated era.data.merge.log model accessible under Data Cleaning → Merge Log. Each entry records the group ID, source records, destination record, merge timestamp, cron user, and any error traceback. Admins can filter the log by model, date range, or outcome (merged / failed).

سجل تدقيق كامل

كل محاولة دمج — ناجحة أو فاشلة — تُكتب في نموذج era.data.merge.log المتاح من تنظيف البيانات → سجل الدمج. يتضمن كل إدخال معرّف المجموعة والسجلات المصدر والوجهة والوقت والمستخدم وأي رسالة خطأ. يمكن تصفية السجل بالنموذج أو النطاق الزمني أو النتيجة.

⚙️

Configurable Limits

Three system parameters drive all behaviour: era_data_merge.batch_size (max merges per cron run), era_data_merge.max_age_days (only process groups older than N days, keeping recent detections under review), and era_data_merge.model_whitelist (comma-separated list such as res.partner,product.product). All are live ir.config_parameter values — no code change or restart needed.

حدود قابلة للتخصيص

ثلاثة معاملات نظام تتحكم في كل السلوك: حجم الدفعة، الحد الأقصى لعمر المجموعة بالأيام، وقائمة النماذج المسموح بمعالجتها (مثل res.partner,product.product). جميعها قيم ir.config_parameter مباشرة — لا تغيير في الكود ولا إعادة تشغيل مطلوبة.

🔗

Respects Odoo Merge Rules

Uses the same ORM merge path that the Data Cleaning UI uses — archives duplicates, transfers related records, updates foreign key references, and triggers the standard _merge() hook on affected models. No custom SQL, no bypassed ORM constraints, no direct table writes. The result is identical to a human clicking Merge in the Data Cleaning interface.

يحترم قواعد الدمج في أودو

يستخدم مسار الدمج عبر ORM المستخدم في واجهة تنظيف البيانات — يؤرشف التكرارات، ينقل السجلات المرتبطة، يُحدّث المراجع، ويُشغّل الخطاف _merge() على النماذج المتأثرة. لا SQL مخصص ولا تجاوز لقيود ORM. النتيجة مطابقة لضغط زر "دمج" في الواجهة.

⏱️

Scheduled & Unattended

The cron is registered under Settings → Technical → Automation → Scheduled Actions → ERA Data Merge. The schedule interval, next execution date, and enabled state are all adjustable from that standard Odoo screen. No dedicated settings page is required — everything runs on standard Odoo ir.cron infrastructure with no extra dependencies.

مُجدوَلة وتعمل تلقائياً

تُسجَّل المهمة في الإعدادات → تقني → الأتمتة → الإجراءات المجدولة → ERA Data Merge. يمكن ضبط الجدول الزمني وتاريخ التنفيذ التالي وحالة التفعيل من تلك الشاشة المعيارية في أودو دون أي صفحة إعدادات إضافية.

How it works

  1. Install the Data Cleaning app + this module from Apps.
  2. Data Cleaning automatically detects and groups duplicates across configured models.
  3. A data manager opens Data Cleaning → Deduplicate Records, reviews each group, and marks ready ones as To Merge.
  4. The ERA cron fires at its scheduled time, reads all To Merge groups, merges each batch via the ORM path, and writes a log entry per group.
  5. Admins review the merge log under Data Cleaning → Merge Log; adjust batch_size or whitelist as needed.

كيف يعمل

  1. ثبّت تطبيق تنظيف البيانات وهذه الوحدة من التطبيقات.
  2. يكتشف التطبيق التكرارات ويجمّعها تلقائياً عبر النماذج المُهيَّأة.
  3. يفتح مدير البيانات تنظيف البيانات → إلغاء التكرارات، يراجع المجموعات، ويضع علامة "جاهز للدمج".
  4. تُشغَّل المهمة في الوقت المحدد، تقرأ المجموعات الجاهزة، تدمجها دفعةً دفعة، وتكتب سجلاً لكل مجموعة.
  5. يراجع المسؤولون سجل الدمج ويضبطون الإعدادات حسب الحاجة.

💡 Tip — Start with Dry-Run  ·  ابدأ بوضع المحاكاة

Before enabling the cron in production, set era_data_merge.dry_run = True and trigger the cron manually from the Scheduled Actions screen. Review the resulting log entries to confirm the correct groups are selected and the destination record choices look right. Then set dry_run = False to go live. The first production run should use a small batch_size (5–10) as an extra safety measure.

قبل تفعيل المهمة في الإنتاج، اضبط era_data_merge.dry_run = True وشغّل المهمة يدوياً من شاشة الإجراءات المجدولة. راجع إدخالات السجل للتأكد من صحة المجموعات المختارة وصحة السجلات الوجهة. ثم اضبط dry_run = False للبدء الفعلي مع حجم دفعة صغير (5–10) كإجراء أمان إضافي.
