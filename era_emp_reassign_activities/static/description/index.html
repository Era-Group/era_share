ERA Employee Reassign Activities

إعادة تعيين أنشطة الموظف من ERA

A single wizard that transfers all future activities, CRM leads, helpdesk tickets, project tasks, sale orders, and purchase RFQs from one Odoo user to another — in one database transaction. Built for offboarding, role changes, and team restructuring.

معالج واحد ينقل جميع الأنشطة المستقبلية وفرص CRM وتذاكر الدعم والمهام وأوامر البيع وطلبات الشراء من مستخدم لآخر — في معاملة قاعدة بيانات واحدة. مصمم لإنهاء الخدمة وتغيير الأدوار وإعادة هيكلة الفرق.

👤

One-Click User Handover

Open the wizard from HR → Employees → Reassign Activities or from Settings → Users. Select the departing user (From) and the replacement user (To), tick the record types to transfer, and click Reassign. The wizard processes every selected record type in a single database transaction — no partial transfers, no orphaned records, and a clean rollback if any step fails.

تسليم المستخدم بنقرة واحدة

افتح المعالج من الموارد البشرية → الموظفون → إعادة تعيين الأنشطة. اختر المستخدم المغادر والمستبدل، ضع علامة على أنواع السجلات، اضغط إعادة التعيين. تتم المعالجة في معاملة واحدة — لا نقل جزئي ولا سجلات يتيمة وتراجع نظيف عند أي خطأ.

📋

Activities & Calendar Events

Reassigns all mail.activity records with date_deadline >= today where user_id matches the source user. The calendar.attendee list on linked calendar.event records is updated so the new owner appears as an attendee and the old owner is removed. Historical (past) activities are left untouched for audit trail purposes.

الأنشطة وأحداث التقويم

تُعاد تعيين جميع سجلات mail.activity المستقبلية التي تطابق المستخدم المصدر. يُحدَّث المشاركون في أحداث التقويم المرتبطة — يُضاف المالك الجديد ويُزال القديم. الأنشطة الماضية تبقى كما هي لأغراض التدقيق.

💼

CRM Leads & Opportunities

Transfers the user_id (salesperson) field on all crm.lead records where active = True and the lead has not been won (probability < 100). Pipeline stages, tags, and expected revenue are preserved exactly. The new owner inherits the full activity log and can pick up every conversation thread seamlessly.

فرص وعملاء CRM

ينقل حقل user_id (البائع) على جميع سجلات crm.lead النشطة غير المُكتسَبة. تُحفظ مراحل المسار والوسوم والإيراد المتوقع دون تغيير. يرث المالك الجديد سجل الأنشطة كاملاً ويمكنه متابعة كل خيط محادثة بسلاسة.

🎫

Helpdesk Tickets

Reassigns open helpdesk.ticket records where user_id matches the source and stage_id.is_close = False. SLA timers are not reset — only the user_id field is updated, so no SLA breach is introduced by the handover. Closed, merged, and cancelled tickets are excluded from the transfer automatically.

تذاكر الدعم الفني

تُعاد تعيين تذاكر helpdesk.ticket المفتوحة المخصصة للمستخدم المصدر. لا تُعاد أوقات SLA — يُحدَّث user_id فحسب دون إحداث خرق اتفاقية الخدمة. التذاكر المغلقة والمُلغاة مستثناة تلقائياً.

🛒

Quotations, Orders & RFQs

Updates user_id on sale.order records in draft or sent state (quotations and sent offers still awaiting a customer response), and on purchase.order records in draft state (RFQs pending approval or sending). Confirmed, locked, and invoiced orders are left untouched to preserve the audit trail.

عروض الأسعار والأوامر وطلبات الشراء

يُحدَّث user_id على عروض البيع في حالة draft أو sent وعلى طلبات الشراء في حالة draft المعلّقة للاعتماد. الأوامر المؤكدة والمُقفلة والمُفوترة تبقى كما هي للحفاظ على سجل التدقيق.

📊

Preview Before Commit

The wizard's first screen displays a summary table: record type, count of records that would be reassigned, and a checkbox to include or exclude each type. Admins can deselect types they want to keep with the original owner — for example, keeping helpdesk tickets assigned to a queue while moving all CRM leads — before clicking the final Reassign button.

معاينة قبل التنفيذ

تعرض الشاشة الأولى للمعالج جدولاً يوضح نوع السجل وعدد السجلات التي ستُعاد تعيينها مع خانة اختيار لكل نوع. يمكن استثناء أنواع بعينها قبل الضغط على زر إعادة التعيين النهائي.

🔒

Access-Controlled

Only users with the HR / Administration group (hr.group_hr_manager) can open the reassignment wizard. The target (To) user must be an active internal user — the system rejects reassignment to portal users, public users, or archived accounts with a clear validation error message, preventing accidental handover to inactive identities.

مُقيَّد بصلاحيات الوصول

فقط مستخدمو مجموعة الموارد البشرية / الإدارة يمكنهم فتح معالج إعادة التعيين. يجب أن يكون المستخدم الهدف مستخدماً داخلياً نشطاً — يرفض النظام النقل إلى مستخدمي البوابة أو الحسابات المؤرشفة برسالة تحقق واضحة.

How it works

  1. Go to HR → Employees → Reassign Activities (or Settings → Users → Reassign).
  2. Select the From user (departing) and the To user (replacement).
  3. Review the record count preview per type; deselect any types to keep with the original owner.
  4. Tick the record types to transfer and click Reassign.
  5. All selected records update in one database transaction — a success summary shows on close.

كيف يعمل

  1. انتقل إلى الموارد البشرية → الموظفون → إعادة تعيين الأنشطة.
  2. اختر المستخدم المصدر (المغادر) والمستخدم الهدف (البديل).
  3. راجع معاينة عدد السجلات لكل نوع وأزل العلامة عن الأنواع التي تريد إبقاءها.
  4. ضع علامة على أنواع السجلات للنقل واضغط إعادة التعيين.
  5. تُحدَّث جميع السجلات المختارة في معاملة واحدة — يظهر ملخص النجاح عند الإغلاق.

ℹ️ Project Tasks & Many-to-Many Assignees  ·  مهام المشاريع والمنفذون المتعددون

Project tasks (project.task where user_ids includes the source user) are fully supported. Because tasks use a many-to-many assignee field, the wizard removes the source user from the user_ids list and adds the target user — other co-assignees on the same task are completely unaffected. Tasks already assigned to the target user are skipped to avoid duplicates.

مهام المشاريع (project.task) مدعومة بالكامل. نظراً لأن المهام تستخدم حقل منفذين many-to-many، يزيل المعالج المستخدم المصدر من قائمة user_ids ويضيف الهدف — المنفذون الآخرون على نفس المهمة لا يتأثرون إطلاقاً. المهام المعيّنة مسبقاً للمستخدم الهدف تُتجاهل لتجنب التكرار.
