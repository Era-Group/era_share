# دليل تثبيت موديول إيرا نسك (era_nusuk)

> **آخر تحديث للدليل:** أغسطس 2026 · مطابق للإصدار 1.0 على فرع `19.0`

---

## المتطلبات الأساسية

### إصدار أودو والاعتماديات

| المتطلب | التفصيل |
|---|---|
| **أودو** | الإصدار **19.0** — **نسخة إنتربرايز** (الموديول يعتمد على `accountant` وهو موديول إنتربرايز) |
| **Python** | 3.10 أو أحدث (حسب متطلبات أودو 19) |
| **PostgreSQL** | 13 أو أحدث |
| **openpyxl** | مكتبة بايثون مطلوبة لقراءة ملف نسك (Excel) في شاشة التأشيرات |
| **wkhtmltopdf** | لإخراج التقارير PDF (بطاقات المعتمرين، كشوف المجموعات…) |

اعتماديات الموديول داخل أودو (تُثبَّت تلقائياً معه):

```python
'depends': ['base', 'mail', 'account', 'contacts', 'accountant']
```

> **تنبيه:** إذا لم تكن نسخة إنتربرايز (موديول `accountant`) متوفرة في مسار
> الإضافات، سيفشل التثبيت عند حل الاعتماديات. لا تحاول الالتفاف بحذف
> الاعتمادية — الفوترة والحسابات التحليلية في العقود تعتمد عليها.

### تثبيت مكتبة openpyxl

```bash
# داخل البيئة الافتراضية التي يعمل منها أودو
pip install openpyxl
```

بدونها يفشل رفع «ملف نسك» على التأشيرة برسالة خطأ استيراد.

## الحصول على الموديول

الموديول جزء من مستودع **era_share** الخاص بمجموعة إيرا:

```bash
git clone -b 19.0 https://github.com/Era-Group/era_share.git
```

مجلد الموديول: `era_share/era_nusuk`

أضف مسار المستودع إلى `addons_path` في ملف تكوين أودو:

```ini
[options]
addons_path = /opt/odoo/enterprise,/opt/odoo/odoo/addons,/path/to/era_share
```

ثم أعد تشغيل خدمة أودو:

```bash
sudo systemctl restart odoo
```

## التثبيت من واجهة أودو

1. فعّل **وضع المطور** (الإعدادات ← أدوات المطور) أو تأكد من صلاحية المدير.
2. انتقل إلى **التطبيقات (Apps)** ← **تحديث قائمة التطبيقات**.
3. ابحث عن **«Era Nusuk Management»** (الاسم التقني: `era_nusuk`).
4. انقر **تثبيت**.

عند التثبيت يُحمَّل تلقائياً:

- **مجموعات الأمان** وقواعدها (`security/umrah_security.xml` و`ir.model.access.csv`).
- **المتسلسلات** (أرقام مراجع التأشيرات والحجوزات والتحركات — `data/sequence.xml`).
- **بيانات الإعداد الأولية** (`data/nusuk_config_data.xml`).

## الإعداد بعد التثبيت

### 1. تعيين الأدوار للمستخدمين

من **الإعدادات ← المستخدمون**، في بطاقة كل مستخدم ابحث عن فئة
**Era Nusuk** واختر الدور:

| الدور | لمن |
|---|---|
| User | اطلاع أساسي |
| Visa Officer | موظفو التأشيرات (لا يعدّلون تأشيرة بعد إصدارها) |
| Operations User | فريق العمليات والنقل |
| Operations Supervisor | مشرفو العمليات (+ شاشات المبيعات والمعالجات) |
| Finance | المالية والفوترة |
| Manager | صلاحية كاملة |
| Agent (Portal) | حسابات الوكلاء الخارجيين عبر البوابة — يرون بياناتهم فقط |

> بدون تعيين دور، لن تظهر أي من تطبيقات نسك الخمسة للمستخدم إطلاقاً —
> كل تطبيق مقيّد بمجموعته الأمنية.

### 2. ضبط الإعدادات العامة

من **الإعدادات ← عام ← قسم Era Nusuk**:

- اشتراط تغطية فندقية / تحركات نقل قبل تقديم التأشيرة (اختياري).
- تفعيل حصة الوكيل الموسمية (اختياري).
- **أرقام أعمدة ملف نسك** (عمود رسوم التأشيرة وعمود الإجمالي) — اضبطها
  لتطابق قالب ملف القسائم المستخدم لديكم.
- نسبة ضريبة القيمة المضافة لرسوم الخدمة.

### 3. إدخال البيانات الأساسية (بالترتيب)

1. **إعدادات المبيعات** (للمدير): أنواع الإشغال، فئات الوكلاء، الخدمات.
2. **إعدادات النقل** (للمشرف): أنواع المواقع ثم المواقع.
3. **شركات النقل والمركبات والسائقون**.
4. **الفنادق وأنواع الغرف** (شاشات الفنادق مخفية حالياً — انظر الملاحظة أدناه).
5. **الوكلاء** ثم اعتمادهم وإدخال أسعارهم.

### 4. الشاشات المخفية (اختياري)

شاشات «المعتمرين» و«الرحلات» وتطبيق «الفنادق» مخفية افتراضياً عبر
`umrah_menu_hide.xml` بقرار تشغيلي. لإظهار أي منها: فعّل **وضع المطور** ثم
من **الإعدادات ← تقني ← قوائم** فعّل القائمة المطلوبة
(مثلاً `menu_nusuk_accommodation_root` لتطبيق الفنادق).

## الترقية والتحديث

عند سحب نسخة أحدث من المستودع:

```bash
cd /path/to/era_share && git pull
sudo systemctl restart odoo
```

ثم حدّث الموديول بإحدى الطريقتين:

- من الواجهة: **التطبيقات** ← Era Nusuk Management ← **ترقية**.
- من الطرفية:

```bash
odoo-bin -c /etc/odoo/odoo.conf -d <database> -u era_nusuk --stop-after-init
```

> **قبل أي ترقية على الإنتاج:** خذ نسخة احتياطية من قاعدة البيانات:
> ```bash
> pg_dump -U odoo -d <database> -Fc -f era_nusuk_backup_$(date +%Y%m%d).dump
> ```

## تشغيل الاختبارات (للمطورين)

الموديول يتضمن اختبارات آلية (`tests/`): محلل ملف نسك، اختبارات المرحلة
الأولى، واختبارات المعالجات. لتشغيلها على قاعدة اختبار:

```bash
odoo-bin -c /etc/odoo/odoo.conf -d <test_database> \
    -i era_nusuk --test-enable --test-tags /era_nusuk --stop-after-init
```

لا تشغّل الاختبارات على قاعدة بيانات الإنتاج.

## استكشاف أخطاء التثبيت

| المشكلة | السبب والحل |
|---|---|
| الموديول لا يظهر في قائمة التطبيقات | تحقق من `addons_path` ثم «تحديث قائمة التطبيقات» بعد إعادة تشغيل أودو |
| فشل التثبيت بسبب موديول `accountant` | نسخة أودو ليست إنتربرايز أو مسار الإنتربرايز غير مضاف إلى `addons_path` |
| خطأ `ModuleNotFoundError: openpyxl` عند رفع ملف نسك | ثبّت `openpyxl` في بيئة أودو الافتراضية وأعد تشغيل الخدمة |
| المستخدم لا يرى أي تطبيق نسك | لم يُعيَّن له دور في فئة «Era Nusuk» ببطاقة المستخدم |
| التقارير PDF لا تُخرَج | تحقق من تثبيت `wkhtmltopdf` وظهوره في سجل بدء تشغيل أودو |
| خطأ صلاحيات بعد الترقية | حدّث الموديول بـ `-u era_nusuk` ليُعاد تحميل ملفات الأمان |

**سجلات النظام:**

```bash
sudo journalctl -u odoo -f          # سجل خدمة أودو
sudo tail -f /var/log/odoo/odoo.log # ملف السجل (حسب التكوين)
```
