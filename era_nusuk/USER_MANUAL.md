## نظرة عامة

موديول **إيرا نسك** هو نظام متكامل لإدارة عمليات العمرة داخل أودو: من عقد العميل
وتسعير الباقات، مروراً بتسجيل المعتمرين وإصدار التأشيرات، إلى إدارة مجموعات
الوصول والإسكان والنقل، وانتهاءً بالفوترة والتقارير.

الموديول مقسّم إلى **خمسة تطبيقات مستقلة**، يظهر كل منها فقط للموظفين أصحاب
الدور المناسب:

| التطبيق | الفريق المستهدف |
|---|---|
| **Nusuk Ops** (عمليات نسك) | فريق العمليات اليومية — المجموعات والتحركات |
| **Nusuk Visas** (تأشيرات نسك) | موظفو التأشيرات |
| **Nusuk Sales** (مبيعات نسك) | فريق المبيعات والمالية — الوكلاء والعقود والباقات |
| **Nusuk Hotels** (فنادق نسك) | فريق الإسكان *(مخفي حالياً بقرار إداري — انظر [الفنادق والحجوزات](#الفنادق-والحجوزات))* |
| **Nusuk Transport** (نقل نسك) | فريق النقل |

**ملاحظة مهمة:** شاشات «المعتمرين» و«الرحلات» وتطبيق «الفنادق» بالكامل
**مخفية حالياً** من القوائم بقرار تشغيلي (عبر `umrah_menu_hide.xml`)، مع بقاء
بياناتها ونماذجها فعّالة لأنها مرتبطة ببقية الشاشات. يمكن لمدير النظام إعادة
تفعيلها من إعدادات القوائم عند الحاجة، ولذلك يوثّق هذا الدليل تلك الشاشات أيضاً.

## الأدوار والصلاحيات

تُدار الصلاحيات من فئة أمان واحدة اسمها **Era Nusuk** (الإعدادات ← المستخدمون ←
بطاقة المستخدم):

| الدور | الصلاحية |
|---|---|
| **User** (مستخدم) | اطلاع أساسي |
| **Visa Officer** (موظف تأشيرات) | يرى تطبيق «Nusuk Visas»؛ **لا يمكنه تعديل تأشيرة بعد إصدارها** (قاعدة أمان مخصصة) |
| **Operations User** (مستخدم عمليات) | يرى تطبيقات العمليات والنقل (والفنادق عند تفعيلها) |
| **Operations Supervisor** (مشرف عمليات) | إضافة إلى ما سبق: يرى «Nusuk Sales»، ومعالج تحديث حالة الرحلة، وقوائم الإعدادات الفرعية |
| **Finance** (مالية) | يرى «Nusuk Sales» والفوترة |
| **Manager** (مدير) | صلاحية كاملة، بما فيها تعديل التأشيرات الصادرة وقائمة إعدادات المبيعات |
| **Agent (Portal)** (وكيل — بوابة) | وصول خارجي مقيّد ببيانات الوكيل نفسه فقط — انظر [بوابة الوكيل](#بوابة-الوكيل) |

## التطبيقات والقوائم

البنية الفعلية للقوائم كما تظهر للمستخدم المخوّل:

```
Nusuk Ops
├── Groups (المجموعات)
├── Movements (التحركات)
└── Update Trip Status (تحديث حالة الرحلة — للمشرف فقط)

Nusuk Visas
├── Pilgrims (المعتمرون — مخفية حالياً)
└── Visas (التأشيرات)

Nusuk Sales
├── Agents (الوكلاء)
├── Packages (الباقات)
├── Customers (العملاء)
├── Customer Contracts (عقود العملاء)
├── Trips (الرحلات — مخفية حالياً)
└── Configuration (للمدير فقط)
    ├── Occupancy Types (أنواع الإشغال)
    ├── Agent Tiers (فئات الوكلاء)
    └── Services (الخدمات)

Nusuk Hotels (مخفي بالكامل حالياً)
├── Hotels (الفنادق)
├── Hotel Bookings (حجوزات الفنادق)
└── Configuration ← Room Types (أنواع الغرف)

Nusuk Transport
├── Transport Programs (برامج النقل)
├── Transport Companies (شركات النقل)
├── Vehicles (المركبات)
├── Drivers (السائقون)
└── Configuration (للمشرف فقط)
    ├── Locations (المواقع)
    └── Location Types (أنواع المواقع)
```

## دورة العمل الكاملة

التسلسل المعتاد لموسم أو دفعة معتمرين، من البداية إلى النهاية:

1. **تهيئة البيانات الأساسية** (مرة واحدة أو موسمياً): الخدمات وأنواع الإشغال
   وفئات الوكلاء (إعدادات المبيعات)، المواقع وأنواعها (إعدادات النقل)،
   شركات النقل والمركبات والسائقون، والفنادق وأنواع الغرف.
2. **اعتماد الوكلاء**: تسجيل الوكيل ← تقديم للموافقة ← اعتماد، ثم إدخال
   أسعاره الخاصة (أسطر التسعير).
3. **تسجيل العميل وعقده**: إنشاء العميل ← إنشاء «عقد عميل» بفترة سريان
   وحساب تحليلي ← تمرير العقد في مسار الاعتماد.
4. **بناء الباقات**: باقة بليالي مكة والمدينة وفندقي الإقامة والخدمات،
   مع أسطر أسعار حسب نوع الإشغال وفئة الوكيل ← اعتماد الباقة.
5. **تكوين المجموعات**: مجموعة لكل دفعة وصول، تُربط بالعقد والباقة والوكيل،
   مع بيانات رحلتي الوصول والمغادرة وفندقي مكة والمدينة وأعضاء المجموعة.
6. **إصدار التأشيرات**: طلب تأشيرة لكل معتمر ← تقديم ← موافقة ← إصدار،
   مع رفع ملف نسك (Excel) لقراءة الرسوم آلياً.
7. **جدولة النقل**: برامج نقل وتحركات (وصول / تنقل بين المدن / مغادرة / زيارة)
   بمساراتها ومركباتها.
8. **التشغيل اليومي**: تحديث حالات المجموعات (غادرت ← في السعودية ← عادت ←
   اكتملت) ومتابعة الحجوزات والتحركات.
9. **الفوترة**: فواتير من المجموعة أو العقد أو التأشيرة أو برنامج النقل،
   وتظهر جميعها لفريق المالية في المحاسبة.
10. **التقارير**: طباعة بطاقات المعتمرين وكشوف المجموعات وتقارير الفنادق
    والنقل من زر **طباعة** في كل شاشة.

## تطبيق نسك المبيعات

### الوكلاء (Agents)

سجل كامل لكل وكيل خارجي: بيانات الشركة والاتصال والعنوان، الترخيص والسجل
الضريبي، البيانات البنكية (بما فيها الآيبان والسويفت)، وجهة اتصال للطوارئ.

**مسار حالة الوكيل** (أزرار أعلى النموذج):

| الحالة | الوصف |
|---|---|
| مسودة (Draft) | تسجيل أولي |
| بانتظار الموافقة (Pending Approval) | بعد زر **تقديم للموافقة** |
| معتمد (Approved) | بعد زر **موافقة** — يُسجَّل اسم المعتمِد |
| موقوف (Suspended) | إيقاف مؤقت — يمكن **إعادة التفعيل** |
| قائمة سوداء (Blacklisted) | منع نهائي |

**تسعير الوكيل**: لكل وكيل أسطر تسعير (سعر بيع وسعر شراء بعملة محددة، مع
فترة سريان «من / إلى»). كما يُصنَّف الوكيل ضمن **فئة وكلاء (Agent Tier)**
تُستخدم في تسعير الباقات.

**حقول مسار**: رقم عقد مسار وتاريخا بدايته ونهايته (انظر [تكامل نسك مسار](#تكامل-نسك-مسار)).

### العملاء (Customers)

بطاقة العميل (الشركة المتعاقدة): جهة الاتصال، الرقم الضريبي، السجل التجاري،
العنوان الكامل، والموظف المسؤول. تمر البطاقة بمسار حالة بسيط قبل الاستخدام.

### عقود العملاء (Customer Contracts)

العقد هو المظلة المالية التي تُربط بها المجموعات والرحلات:

- **الحقول الأساسية**: العميل، فترة السريان (من / إلى)، **الخطة التحليلية
  والحساب التحليلي** (لتوزيع التكاليف والإيرادات في المحاسبة).
- **مسار الحالة**: مسودة ← مقدَّم ← بانتظار الاعتماد ← معتمد / ملغى،
  مع زر **إعادة إلى مسودة**.
- **الأزرار الذكية** أعلى النموذج تعرض كل ما يتبع العقد: المجموعات،
  الرحلات، المعتمرون، برامج النقل، الحجوزات، والفواتير.
- زر **إنشاء فاتورة** يولّد فاتورة العقد مباشرة.

### الباقات (Packages)

الباقة هي المنتَج المسعَّر الذي يُباع للوكلاء:

- **المكوّنات**: عدد ليالي مكة وليالي المدينة (ويُحسب الإجمالي)، فندق مكة
  وفندق المدينة، وقائمة **الخدمات** المشمولة (من إعدادات المبيعات).
- **أسطر الأسعار**: لكل سطر نوع إشغال (ثنائي، ثلاثي، رباعي…) وفئة وكيل
  وسعر بيع وسعر تكلفة وفترة سريان — فيتحدد سعر الباقة تلقائياً حسب الوكيل
  ونوع الغرفة والتاريخ.
- **مسار الحالة**: مسودة ← معتمدة ← مؤرشفة.
- **مرجع مسار**: حقل «Masar Program Ref» لأن الباقات تُسجَّل في منصة مسار.

### الرحلات (Trips) — *شاشة مخفية حالياً*

سجل الرحلة (التاريخ والوجهة والسعة) بمسار حالة: مسودة ← مؤكدة ← قيد
التنفيذ ← مكتملة / ملغاة، مع أزرار ذكية للمجموعات والمعتمرين والحجوزات.
تُحدَّث حالتها جماعياً من معالج **تحديث حالة الرحلة** في تطبيق العمليات.

### إعدادات المبيعات (للمدير)

| القائمة | الغرض |
|---|---|
| **أنواع الإشغال** | ثنائي / ثلاثي / رباعي… تُستخدم في أسطر أسعار الباقات |
| **فئات الوكلاء** | شرائح تسعير (ذهبي / فضي…) تُربط بالوكلاء وأسطر الأسعار |
| **الخدمات** | الخدمات القابلة للتضمين في الباقات (إعاشة، إرشاد، زيارات…) |

## تطبيق نسك التأشيرات

### المعتمرون (Pilgrims) — *الشاشة مخفية حالياً*

سجل المعتمر: **الاسم الكامل** (حقل واحد)، الجنس، الجنسية، بيانات الجواز
والاتصال وجهة الطوارئ. يُنشأ المعتمرون غالباً من شاشات المجموعات
والتأشيرات، ويظل سجلهم مرجعاً لكل الشاشات الأخرى.

**مسار حالة المعتمر**: مسودة ← مؤكد ← قُدّمت التأشيرة ← اعتُمدت التأشيرة ←
غادر ← عاد، أو ملغى.

### التأشيرات (Visas)

الشاشة الرئيسية لموظف التأشيرات. لكل طلب:

- **الأساسيات**: المعتمر، نوع التأشيرة (عمرة / حج / زيارة / عمل)، نوع
  الدخول (مفرد / متعدد)، تواريخ الإصدار والانتهاء، الوكيل المعالج.
- **الرسوم والدفع**: رسوم التأشيرة ورسوم الخدمة، وحالة الدفع
  (غير مدفوعة / جزئية / مدفوعة / مستردة).

**مسار حالة التأشيرة** (أزرار أعلى النموذج):

```
مسودة ← تقديم (Submitted) ← قيد المراجعة ← موافقة (Approved) ← إصدار (Issued)
                                        ↳ رفض (Rejected)
بعد الإصدار: مفوترة (Invoiced) / منتهية (Expired) — أو إلغاء في أي مرحلة
```

> **قاعدة أمان:** بعد وصول التأشيرة لحالة «صادرة» لا يستطيع موظف التأشيرات
> تعديلها — التعديل للمدير فقط.

**ملف نسك (Excel)**: يمكن رفع ملف قسائم نسك (Voucher List) على التأشيرة في
حقل «Nusuk Visa File»؛ يقرأ النظام منه **رسوم التأشيرة والإجمالي الكلي**
تلقائياً (رقما العمودين قابلان للضبط في [الإعدادات العامة](#الإعدادات-العامة)).
إن تعذّرت القراءة تظهر رسالة «Nusuk File Error» — تحقق من أن الملف بصيغة
Excel الصحيحة وأن أرقام الأعمدة في الإعدادات مطابقة للملف.

**الفوترة من التأشيرة**:

- **إنشاء فاتورة تأشيرة** — فاتورة برسوم التأشيرة.
- **إنشاء فاتورة وكيل** — فاتورة على الوكيل المعالج.
- تدعم الشيفرة أيضاً إنشاء **فواتير وكلاء جماعية** لمجموعة تأشيرات دفعة
  واحدة (معالج «Bulk Invoice Visa Application» — غير مربوط بقائمة ظاهرة
  حالياً؛ يفعّله مدير النظام عند الحاجة).

## تطبيق نسك العمليات

### المجموعات (Groups) — الشاشة المحورية للتشغيل

المجموعة تمثل دفعة وصول واحدة، وتجمع كل خيوط العملية:

- **الهوية**: الاسم، الرمز، النوع (عائلية / أصدقاء / مؤسسة / مختلطة / VIP)،
  القائد (من المعتمرين)، المرشد، الوكيل، **رقم مجموعة مسار**.
- **الطيران**: رقم رحلة الوصول ومطارها وتاريخها، ومثلها للمغادرة.
- **الإسكان**: فندق مكة وفندق المدينة، وترتبط بها حجوزات الفنادق.
- **الربط التجاري**: الباقة، عقد العميل، والرحلات.
- **الأعضاء**: تبويب أعضاء المجموعة (كل عضو سجل يربط معتمراً بالمجموعة)،
  مع عدّادات السعة والمقاعد المتاحة.
- **قيود اختيارية**: قيود الجنس والعمر، متطلبات خاصة، وروابط مجموعات
  واتساب وتليجرام.

**مسار حالة المجموعة** (أزرار متتابعة أعلى النموذج):

```
مسودة ← قيد التكوين ← مؤكدة ← غادرت ← في السعودية ← عادت ← مكتملة
                                                (أو ملغاة في أي مرحلة)
```

**أزرار ذكية وإجراءات**: عرض الرحلات وبرامج النقل والحجوزات والمعتمرين
والفواتير المرتبطة، وزر **إنشاء فاتورة** لفوترة المجموعة، وزر
**طباعة بطاقات المعتمرين** لإخراج بطاقات كل الأعضاء دفعة واحدة.

### التحركات (Movements)

طلب نقل موحّد يعكس أنواع طلبات **نسك مسار**:

| النوع | الاستخدام |
|---|---|
| وصول (Arrival) | من المطار إلى الفندق |
| تنقّل بين المدن (Intercity) | مكة ↔ المدينة |
| مغادرة (Departure) | من الفندق إلى المطار |
| زيارة (Ziyarah) | جولات المشاعر والمزارات |
| أخرى (Other) | أي تحرك محلي آخر |

لكل تحرك: مرجع تسلسلي تلقائي، **مرجع طلب مسار**، رقم الرحلة الجوية، شركة
النقل، فترة التنفيذ، ثم ثلاثة تبويبات:

- **المسارات**: أسطر «من موقع / إلى موقع» مع وقتي الانطلاق والوصول.
- **المركبات**: المركبات المخصصة وسعة ركاب كل منها.
- **المجموعات**: المجموعات المنقولة — وتُحسب منها قائمة المعتمرين
  وعددهم تلقائياً.

> شاشة التحركات **تشغيلية فقط ولا تُصدر فواتير** — فوترة النقل تتم من
> برنامج النقل في تطبيق النقل.

### تحديث حالة الرحلة (للمشرف)

معالج يُحدّث حالة رحلة كاملة دفعة واحدة، مع خيار سحب التحديث على حالات
المجموعات والمعتمرين التابعين لها — بدلاً من فتح السجلات واحداً واحداً.

## تطبيق نسك النقل

### برامج النقل (Transport Programs)

البرنامج هو الخطة الكاملة لنقل مجموعة أو أكثر: مساراته (مواقع وأوقات)،
مركباته المخصصة، والمجموعات المستفيدة، مع أزرار ذكية لعرض المجموعات
والمعتمرين، وزر **إنشاء فاتورة نقل** لفوترة البرنامج.

### شركات النقل والمركبات والسائقون

- **شركات النقل**: بطاقة لكل ناقل (مرتبطة بجهة اتصال أودو) تُستخدم في
  البرامج والتحركات.
- **المركبات**: لكل مركبة اسم ولوحة وسعة ركاب وحالة تشغيلية، مع تتبع
  للمراسلات (Chatter).
- **السائقون**: سجل السائق ببياناته ورخصته.

### إعدادات النقل (للمشرف)

- **المواقع**: كل نقطة انطلاق أو وصول (مطار، فندق، الحرم، ميقات…).
- **أنواع المواقع**: تصنيف المواقع (مطار / فندق / مزار…).

## الفنادق والحجوزات

> تطبيق «Nusuk Hotels» **مخفي حالياً بالكامل** بقرار إداري. البيانات
> والنماذج فعّالة، وتظهر الحجوزات من خلال المجموعات والعقود. لإعادة إظهار
> التطبيق يفعّل مدير النظام قائمة `menu_nusuk_accommodation_root`.

### الفنادق (Hotels)

بطاقة الفندق: المدينة (مكة / المدينة / جدة / أخرى)، تصنيف النجوم (1–5)،
عدد الغرف، المسافة من الحرم، بيانات الاتصال، والمرافق.

### أنواع الغرف (Room Types)

لكل فندق أنواع غرف بسعتها ونوع أسرّتها (مفرد / مزدوج / توأم / ثلاثي /
رباعي) وإطلالتها (على الحرم / المدينة / الفناء / بدون) وسعر الليلة.

### حجوزات الفنادق (Hotel Bookings)

- **الحجز**: مرجع تلقائي، الفندق ونوع الغرفة، فترة الإقامة، خطة الوجبات
  (بدون / إفطار / نصف إقامة / إقامة كاملة)، وأسطر الغرف المحجوزة.
- **مسار الحالة**: مسودة ← مؤكد ← تم تسجيل الدخول ← تمت المغادرة / ملغى.
- **حالة مسار** مستقلة لكل حجز: بانتظار الموافقة / معتمد / مرفوض، مع
  **مرجع موافقة مسار**.

## تكامل نسك مسار

الموديول مبني ليجاري منصة **نسك مسار** الحكومية، عبر حقول مرجعية يدوية
في الشاشات المعنية (لا يوجد ربط آلي مباشر — تُنقل الأرقام من مسار وإليها):

| الشاشة | حقول مسار |
|---|---|
| الوكيل | رقم عقد مسار + فترة سريانه |
| المجموعة | رقم مجموعة مسار |
| الباقة | مرجع برنامج مسار |
| حجز الفندق | مرجع موافقة مسار + حالة مسار (بانتظار / معتمد / مرفوض) |
| التحرك | مرجع طلب النقل في مسار |
| التأشيرة | ملف نسك (Excel) لقراءة الرسوم |

**القاعدة العملية**: عند استلام أي اعتماد من مسار، سجّل مرجعه فوراً في
الحقل المقابل حتى يسهل التدقيق والمطابقة لاحقاً.

## بوابة الوكيل

يمكن منح الوكيل الخارجي حساب **بوابة (Portal)** مع دور «Agent (Portal)»،
فيرى عبر البوابة **بياناته هو فقط** (قواعد أمان مقيّدة بسجل الوكيل):

- بطاقة الوكيل الخاصة به وأسعاره.
- مجموعاته وأعضاؤها ومعتمروه.
- تأشيرات معتمريه وحالتها.
- رحلاته وبرامج نقله وتحركاته.

لا يرى الوكيل أي بيانات لوكلاء آخرين، ولا شاشات الإعداد أو الفوترة الداخلية.

## استكشاف الأخطاء وإصلاحها

| العرض | السبب المرجّح والحل |
|---|---|
| لا أرى تطبيقاً من تطبيقات نسك | ينقصك دور الصلاحية المناسب — اطلب من المدير ضبط فئة «Era Nusuk» في بطاقة مستخدمك |
| لا أجد شاشة المعتمرين / الرحلات / الفنادق | هذه الشاشات مخفية حالياً بقرار إداري؛ يمكن للمدير إعادة تفعيل قوائمها |
| رسالة «Nusuk File Error» عند رفع ملف التأشيرات | الملف ليس بصيغة Excel الصحيحة، أو أرقام الأعمدة في الإعدادات لا تطابق الملف |
| لا أستطيع تعديل تأشيرة | التأشيرة صادرة، وتعديلها بعد الإصدار حكر على المدير |
| لا أستطيع تقديم تأشيرة | قد يكون أحد اشتراطات الإعدادات مفعّلاً (تغطية فندقية / تحركات نقل / حصة الوكيل) دون استيفائه |
| زر إنشاء الفاتورة لا يعمل | تأكد من اكتمال البيانات المالية (العقد معتمد، الأسعار مدخلة) ومن صلاحية «Finance» أو أعلى |
| لا تظهر سجلات في القائمة | راجع المرشحات المفعّلة في شريط البحث، أو أنك وكيل بوابة ترى سجلاتك فقط |
