How it works

Four steps, none of them manual

أربع خطوات، لا يدوية فيها

From the moment Sembly closes the meeting to the note in your chatter.

من لحظة إغلاق Sembly للاجتماع حتى الملاحظة في الشاتر.

1

Pull

السحب

An MCP client against mcp.sembly.ai brings in metadata, minutes, decisions, risks and action items — and backfills your history.

عميل MCP يتصل بـ mcp.sembly.ai ليجلب البيانات والملخص والقرارات والمخاطر والمهام — ويستورد السجل التاريخي.

2

Complete

الاكتمال

A Sembly automation webhook adds what MCP does not carry: the transcript, the recording link and participant emails.

ويب هوك من أتمتة Sembly يضيف ما لا يوفره MCP: التفريغ النصي ورابط التسجيل وبريد المشاركين.

3

Link

الربط

Candidates are narrowed deterministically first, then the AI picks one. Confidence ≥ 0.7 links; below it you get a one-click suggestion.

تُختصر المرشحات بقواعد ثابتة أولًا ثم يختار الذكاء الاصطناعي واحدًا. الثقة ≥ 0.7 تربط تلقائيًا، وما دونها اقتراح بنقرة.

4

Post

النشر

The latest meeting of today or yesterday — in your company timezone — is written into the chatter as an internal note, exactly once.

أحدث اجتماع لليوم أو أمس — بتوقيت شركتك — يُكتب في الشاتر كملاحظة داخلية، مرة واحدة بالضبط.

Architecture

Two channels, one record

قناتان، وسجل واحد

Capability MCP (pull) Webhook (push)
Metadata — title, times, duration, platform, owner ✓ ✓
Participants ✓ names ✓ emails
Summary / minutes ✓ ✓
Decisions, issues, risks, requirements, highlights ✓ ✗
Transcript ✗ ✓
Recording link ✗ ✓
Historical backfill ✓ ✗ future only
On-demand re-fetch ✓ ✗

Neither channel alone is enough, so both converge on one sembly.meeting record keyed by the Sembly meeting id — arrival order never matters.

لا تكفي أي قناة بمفردها، لذا تلتقي القناتان على سجل sembly.meeting واحد مفتاحه معرف الاجتماع — وترتيب الوصول لا يهم.

In your workflow

Where the meetings show up

أين تظهر الاجتماعات؟

💼

On all four record types

على الأنواع الأربعة جميعًا

Opportunity, project, task and ticket each carry the same smart button with a live count, and each receives the latest summary as an internal note in its chatter.

الفرصة والمشروع والمهمة والتذكرة تحمل الزر الذكي نفسه بعدّاد مباشر، ويصل كلًا منها أحدث ملخص كملاحظة داخلية في الشاتر.

🔍

In their own app

في تطبيق مستقل

A dedicated الاجتماعات app with list, kanban, calendar and form views, filters by link state, and a manual import wizard for history.

تطبيق الاجتماعات بعروض القائمة والكانبان والتقويم والنموذج، مع فلاتر حسب حالة الربط ومعالج استيراد يدوي.

The fallback rule: opportunity or task or ticket first; if none of them matches but a project does, the project's الاجتماعات bucket task; and if nothing matches at all, the meeting stays unlinked in the app for a human to place by hand — it is never attached to a guess.

قاعدة البديل: الفرصة أو المهمة أو التذكرة أولًا؛ فإن لم يتطابق أي منها وتطابق مشروع، فمهمة الاجتماعات الخاصة به؛ وإن لم يتطابق شيء إطلاقًا بقي الاجتماع غير مرتبط ليضعه إنسان بيده — ولا يُلحق بتخمين أبدًا.

🔒 The transcript never reaches the model

🔒 التفريغ النصي لا يصل إلى النموذج أبدًا

When a meeting is matched, only the title, the date, the participant names and the first 2 000 characters of the summary leave the instance. The transcript is stored in Odoo and is never part of a prompt — a deliberate data-minimisation policy, not an implementation detail.

عند المطابقة لا يغادر الخادم سوى العنوان والتاريخ وأسماء المشاركين وأول 2 000 حرف من الملخص. أما التفريغ فيُحفظ في أودو ولا يدخل أي مُوجَّه — سياسة تقليل بيانات مقصودة، لا تفصيلة تنفيذية.

Setup

Live in four steps

التشغيل في أربع خطوات

Nothing reaches Sembly until step 1, so the module is inert on install.

لا شيء يصل إلى Sembly قبل الخطوة الأولى، فالوحدة خاملة عند التثبيت.

1

Enter the MCP token

أدخل رمز MCP

Settings → Sembly. Nothing reaches Sembly before this. SEMBLY_MCP_TOKEN keeps the secret out of the database.

الإعدادات ← Sembly. لا شيء يصل إلى Sembly قبل ذلك. ومتغير SEMBLY_MCP_TOKEN يبقي السر خارج قاعدة البيانات.

2

Paste the webhook URL

الصق رابط الويب هوك

The settings page shows it. Create two Sembly automations pointing at it — one for Transcription, one for Notes.

صفحة الإعدادات تعرضه. أنشئ أتمتتين في Sembly تشيران إليه — واحدة للتفريغ وأخرى للملاحظات.

3

Enable the three crons

فعّل المهام المجدولة الثلاث

Sync, AI matching and chatter posting ship disabled, so installing can never spend AI budget before a human says so.

المزامنة والمطابقة بالذكاء والنشر في الشاتر تُشحن معطلة، فلا ينفق التثبيت رصيدًا قبل موافقة إنسان.

4

Backfill your history

استورد سجلك التاريخي

الاجتماعات → الإعدادات → استيراد من Sembly. The webhook only ever sees future meetings, so this is the only way in for past ones.

الاجتماعات ← الإعدادات ← استيراد من Sembly، فالويب هوك لا يرى إلا الاجتماعات القادمة.

🧩 One base app, three link modules

🧩 تطبيق أساسي واحد، وثلاث وحدات ربط

This app owns the meeting, both Sembly channels, the AI machinery and the chatter posting — and depends on nothing but mail and ai, so it installs anywhere. Each link target ships separately and installs itself once its own app is present: era_sembly_meetings_crm (opportunity), era_sembly_meetings_tasks (project, task and the الاجتماعات bucket task) and era_sembly_meetings_tickets (helpdesk ticket). Install one, two or all three; uninstall any of them and the rest carry on untouched.

يملك هذا التطبيق الاجتماع وقناتَي Sembly وآلة الذكاء الاصطناعي والنشر في الشاتر — ولا يعتمد إلا على mail وai، فيُثبَّت في أي مكان. وتأتي كل جهة ربط في وحدة مستقلة تُثبَّت وحدها متى وُجد تطبيقها: era_sembly_meetings_crm (الفرصة)، وera_sembly_meetings_tasks (المشروع والمهمة وتاسك الاجتماعات)، وera_sembly_meetings_tickets (تذكرة مكتب المساعدة). ثبّت واحدة أو اثنتين أو الثلاث؛ وإلغاء أي منها لا يمسّ البقية.
