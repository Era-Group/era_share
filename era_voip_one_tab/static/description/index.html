ERA VoIP One Tab

تسجيل SIP لتبويب واحد من ERA

Solve the multiple-tab SIP storm problem once and for all — enforce a single active SIP registration per user across all open browser tabs, eliminate ghost rings and audio conflicts, and connect only when a call is actually in progress.

احلّ مشكلة تسجيل SIP في تبويبات متعددة مرة واحدة وللأبد — أبقِ تسجيلاً SIP واحداً نشطاً لكل مستخدم عبر جميع تبويبات المتصفح المفتوحة، وأزل المكالمات الوهمية وتعارضات الصوت، واتصل فقط عندما تكون هناك مكالمة فعلية.

🎯

Single Active Registration

Uses the browser's BroadcastChannel API to negotiate a "primary tab" across all open Odoo tabs for the same user. Only the primary tab registers with the SIP server — all other tabs stay idle.

When the primary tab closes, a remaining tab automatically takes over leadership within 2 seconds, with no user action needed.

تسجيل نشط واحد

يستخدم واجهة BroadcastChannel في المتصفح للتفاوض على "التبويب الأساسي" عبر جميع تبويبات أودو المفتوحة للمستخدم نفسه. التبويب الأساسي فقط يسجّل مع خادم SIP — باقي التبويبات تبقى خاملة. عند إغلاق التبويب الأساسي، يتولى تبويب آخر القيادة خلال ثانيتين تلقائياً.

📵

Connect-on-Call-Only Mode

Even the primary tab can be configured to avoid a persistent SIP registration. It connects (REGISTER) only when a call is initiated or the softphone widget is opened, and disconnects (DEREGISTER) when the call ends and the widget closes.

This halves SIP server load for large deployments and keeps the server free of unnecessary REGISTER storms between calls.

وضع الاتصال عند المكالمة فقط

يمكن تهيئة التبويب الأساسي لتجنب التسجيل المستمر في SIP. يتصل (REGISTER) فقط عند بدء مكالمة أو فتح واجهة الهاتف، ويقطع الاتصال (DEREGISTER) عند انتهاء المكالمة وإغلاق الواجهة. يُقلّل هذا حمل خادم SIP إلى النصف في النشرات الكبيرة ويحافظ على الخادم خالياً من عواصف REGISTER غير الضرورية.

🔇

Eliminates Ghost Calls

Without this module, an incoming call triggers a ringing event in every open tab simultaneously — multiple ring sounds, multiple answer buttons, audio routed to whichever tab responds first.

With it, only the primary tab receives the SIP INVITE and rings — one notification, one answer button, clean audio. No more frantic tab-hunting when the phone rings.

إزالة المكالمات الوهمية

بدون هذه الوحدة، تُطلق المكالمة الواردة رنيناً في كل تبويب مفتوح في آنٍ واحد — أصوات رنين متعددة وأزرار إجابة متعددة والصوت يذهب لأول تبويب يستجيب. مع الوحدة، فقط التبويب الأساسي يستقبل INVITE ويرنّ — إشعار واحد وزر إجابة واحد وصوت نظيف بلا تعارض.

🔐

Permission-Based Opt-In

A new security group VoIP One Tab User controls who gets the single-tab behaviour. Users not in the group retain the default Odoo VoIP registration model.

This lets you roll out the feature gradually, test with a subset of your team, or keep specific power users on the legacy multi-tab registration if their workflow demands it.

تفعيل قائم على الأذونات

مجموعة أمان جديدة VoIP One Tab User تتحكم في من يحصل على سلوك التبويب الواحد. المستخدمون غير المنتمين للمجموعة يحتفظون بنموذج تسجيل Odoo VoIP الافتراضي. يتيح ذلك الطرح التدريجي أو الاختبار مع فريق فرعي أو إبقاء مستخدمين محددين على النموذج القديم.

⚙️

Configurable in Settings

Admins can toggle "Connect on call only" vs "Always registered" and "One tab mode" vs "All tabs mode" from a dedicated section in Settings → VoIP → ERA VoIP. Changes take effect on next browser reload.

No code edits, no config files — everything is in the standard Odoo settings UI, with clear descriptions for each option.

قابل للتهيئة من الإعدادات

يمكن للمديرين تبديل "الاتصال عند المكالمة فقط" مقابل "مسجّل دائماً" و"وضع التبويب الواحد" مقابل "جميع التبويبات" من قسم مخصص في الإعدادات. التغييرات تسري عند إعادة تحميل المتصفح. لا تعديلات كود ولا ملفات إعداد — كل شيء في واجهة إعدادات أودو القياسية.

⚡

Zero Call-Quality Impact

The connect-on-call-only approach adds approximately 200 ms to call setup time (the REGISTER round trip) — imperceptible in practice. SIP re-registration after a network disruption is handled automatically by the Odoo VoIP JavaScript stack.

Audio quality, codec negotiation, and DTMF signalling are completely unaffected by the single-tab enforcement.

لا تأثير على جودة المكالمة

نهج الاتصال عند المكالمة فقط يُضيف حوالي 200 مللي ثانية لوقت إعداد المكالمة (رحلة REGISTER ذهاباً وإياباً) — غير ملحوظة عملياً. إعادة التسجيل SIP بعد انقطاع الشبكة يعالجها تلقائياً مكدس JavaScript لـ VoIP في أودو. جودة الصوت وتفاوض الترميز وإشارات DTMF لا تتأثر على الإطلاق.

How it works

  1. Install module and assign the VoIP One Tab User permission group to the relevant users.
  2. User opens Odoo in 3 browser tabs → Tab 1 wins the BroadcastChannel election and becomes primary; Tabs 2 & 3 are idle.
  3. Incoming call arrives at the SIP server → only Tab 1 receives the INVITE and rings.
  4. User answers in Tab 1; audio flows cleanly with no conflict from other tabs.
  5. Call ends → primary tab sends DEREGISTER (if connect-on-call-only is enabled).
  6. If Tab 1 closes, Tab 2 wins a new election and takes over SIP registration within 2 seconds.

كيف يعمل

  1. ثبّت الوحدة وامنح مجموعة الأذونات VoIP One Tab User للمستخدمين المعنيين.
  2. يفتح المستخدم أودو في 3 تبويبات → التبويب 1 يفوز في انتخاب BroadcastChannel ويصبح أساسياً؛ التبويبان 2 و3 خاملان.
  3. تصل مكالمة واردة لخادم SIP → فقط التبويب 1 يستقبل INVITE ويرنّ.
  4. يُجيب المستخدم في التبويب 1؛ الصوت يتدفق بنظافة دون تعارض.
  5. تنتهي المكالمة → التبويب الأساسي يرسل DEREGISTER (إذا كان وضع الاتصال عند المكالمة مفعّلاً).
  6. إذا أُغلق التبويب 1، يفوز التبويب 2 في انتخاب جديد ويتولى تسجيل SIP خلال ثانيتين.

🖥️ Why this matters for large teams

In a call centre with 50 agents each having 3 browser tabs open, the SIP server receives up to 150 REGISTER messages on startup instead of 50 — a 3× storm that can trigger SIP server throttling or rate-limiting. This module cuts that back to 50 regardless of how many tabs each agent has open.

في مركز اتصال بـ 50 وكيلاً لكل منهم 3 تبويبات مفتوحة، يستقبل خادم SIP ما يصل إلى 150 رسالة REGISTER عند الإطلاق بدلاً من 50 — عاصفة 3 أضعاف قد تُشغّل تحديد معدل الخادم. هذه الوحدة تُعيدها إلى 50 بغض النظر عن عدد التبويبات المفتوحة.

ℹ️ Requires Odoo VoIP

This module patches the standard Odoo voip module's JavaScript registration layer. It does not replace or bundle its own SIP stack — it relies on Odoo's built-in sip.js integration. No third-party SIP libraries are included; the call quality is entirely determined by your SIP provider and network.

تُصحح هذه الوحدة طبقة تسجيل JavaScript لوحدة voip القياسية في أودو. لا تستبدل مكدس SIP الخاص بها — تعتمد على تكامل sip.js المدمج في أودو. لا مكتبات SIP خارجية مضمنة؛ جودة المكالمة تحددها بالكامل شبكتك ومزوّد SIP الخاص بك.
